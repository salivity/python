Python inspect.getmro() and Method Resolution Order

When examining class inheritance hierarchies in Python, inspect.getmro(cls) returns a tuple of classes representing the Method Resolution Order (MRO) for the specified class. This article explains the structure of the returned tuple, how Python constructs this sequence using the C3 linearization algorithm, and how developers can use the inspect module to inspect attribute and method lookup paths in complex inheritance structures.

The Return Value of inspect.getmro()

The inspect.getmro() function belongs to Python's standard inspect module. When passed a class object, it returns a tuple of class objects.

The sequence inside the tuple follows strict rules:

  1. Starting Point: The first element is always the target class itself.
  2. Intermediate Bases: The subsequent elements are the base classes, ordered according to the C3 linearization algorithm used by Python to resolve multiple inheritance.
  3. Termination: The final element is always the built-in object class, which serves as the root of all classes in Python 3.

Practical Example

Consider a classic multiple inheritance hierarchy (the diamond problem):

import inspect

class Base:
    pass

class Left(Base):
    pass

class Right(Base):
    pass

class Child(Left, Right):
    pass

# Retrieve the MRO using inspect.getmro()
mro_result = inspect.getmro(Child)

print(type(mro_result))
print(mro_result)

Output:

<class 'tuple'>
(<class '__main__.Child'>, <class '__main__.Left'>, <class '__main__.Right'>, <class '__main__.Base'>, <class 'object'>)

In this output, inspect.getmro(Child) reveals the precise lookup sequence Python follows when searching for an attribute or method on an instance of Child. If a method is not found in Child, Python checks Left, then Right, followed by Base, and finally object.

Comparison with cls.__mro__

The return value of inspect.getmro(cls) is identical to accessing the __mro__ attribute directly on a class:

Child.__mro__ == inspect.getmro(Child)  # Returns True

While accessing cls.__mro__ directly is common, using inspect.getmro() provides consistent, readable code when performing reflective tasks alongside other functions from the inspect module.

Common Use Cases

  • Debugging Multiple Inheritance: Identifying unexpected method overrides or resolution conflicts in complex frameworks.
  • Metaprogramming and Framework Design: Scanning an entire inheritance tree to register plugins, collect class-level metadata, or validate API contracts across base classes.
  • Type and Mixin Checking: Determining whether a class incorporates a specific mixin or interface anywhere within its hierarchy.
