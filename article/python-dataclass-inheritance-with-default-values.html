Python Dataclass Inheritance With Default Values

Inheriting from a Python dataclass involves specific rules regarding field ordering and default values. When a subclass inherits from a base dataclass, Python constructs the __init__ method by concatenating the fields of the base class with the fields of the subclass. Because Python functions do not allow non-default arguments to follow default arguments, adding a field without a default value in a subclass when the base class already contains fields with default values results in a TypeError. This article explains how field ordering works, why this error occurs, and the solutions available to resolve it.

How Field Ordering Works in Dataclasses

When dataclasses are subclassed, Python traverses the inheritance tree (following the Method Resolution Order) and orders the fields for the generated __init__ method as follows:

  1. Fields from the base class (in the order they were defined).
  2. Fields from the subclass (in the order they were defined).

For example:

from dataclasses import dataclass

@dataclass
class Base:
    a: int
    b: int

@dataclass
class Child(Base):
    c: int

The resulting __init__ signature for Child is __init__(self, a: int, b: int, c: int).

The Default Value Conflict

Python syntax dictates that any parameter without a default value cannot appear after a parameter that has a default value. When dataclass inheritance combines fields, this rule remains strictly enforced.

Consider this invalid structure:

from dataclasses import dataclass

@dataclass
class Base:
    a: int = 10  # Has a default value

@dataclass
class Child(Base):
    b: int       # No default value

During compilation, Python generates an __init__ signature resembling:

def __init__(self, a: int = 10, b: int):
    ...

Because non-default argument b follows default argument a, Python raises a TypeError: TypeError: non-default argument 'b' follows default argument

Solutions

1. Assign Default Values in the Subclass

The simplest fix is to provide default values for all fields introduced in the subclass:

from dataclasses import dataclass

@dataclass
class Base:
    a: int = 10

@dataclass
class Child(Base):
    b: int = 20

This generates __init__(self, a: int = 10, b: int = 20), which is fully valid.

2. Use Keyword-Only Arguments (Python 3.10+)

In Python 3.10 and later, keyword-only arguments eliminate the requirement that non-default arguments must precede default arguments. You can make fields keyword-only at the class level using kw_only=True:

from dataclasses import dataclass

@dataclass(kw_only=True)
class Base:
    a: int = 10

@dataclass(kw_only=True)
class Child(Base):
    b: int

This produces an __init__ signature of __init__(self, *, a: int = 10, b: int), which is valid Python syntax because positional argument constraints no longer apply. Instantiation requires keyword arguments:

instance = Child(b=5)

Alternatively, you can apply kw_only=True to specific individual fields using dataclasses.field(kw_only=True).

3. Override Fields in the Subclass

If you need a base field with a default to behave differently, you can redefine it in the subclass:

from dataclasses import dataclass

@dataclass
class Base:
    a: int = 10

@dataclass
class Child(Base):
    a: int
    b: int

Redefining a in Child without a default value removes its default assignment, allowing both a and b to exist as standard positional arguments without defaults.
