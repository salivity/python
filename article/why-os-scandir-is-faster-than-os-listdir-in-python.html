Why os.scandir Is Faster Than os.listdir in Python

Python's os.scandir() outperforms os.listdir() during filesystem traversals by significantly reducing the number of expensive system calls required to inspect directory contents. While os.listdir() returns a simple list of filename strings, requiring additional system calls to determine whether an item is a file, directory, or symlink, os.scandir() yields an iterator of os.DirEntry objects. These objects capture and expose the file attribute metadata that modern operating systems already retrieve while reading directory structures, eliminating the need for subsequent stat operations and drastically accelerating traversal speeds.

The System Call Bottleneck in os.listdir()

When you use os.listdir(), Python requests only the names of the entries within a directory. If your code needs to do anything useful with those entries—such as filtering directories, finding file sizes, or modifying file permissions—you must invoke functions like os.path.isdir(), os.path.isfile(), or os.stat().

Every time one of these functions is called on a path string, the operating system must execute a separate stat system call (stat() or lstat() on POSIX systems, and GetFileAttributesEx() on Windows). In a directory containing 10,000 files, checking whether each item is a directory requires:

  1. One system call to read the directory via os.listdir().
  2. 10,000 independent stat system calls to inspect each file.

These redundant kernel context switches create massive I/O overhead, particularly across network filesystems (NFS, SMB) and spinning hard disks, leading to slow traversal times.

How os.scandir() Optimizes Metadata Retrieval

Introduced via PEP 471, os.scandir() interacts directly with the operating system’s underlying directory-reading APIs:

  • POSIX: Functions like readdir() return a dirent structure that often includes a d_type field containing the file type.
  • Windows: The FindFirstFileW and FindNextFileW system APIs return a WIN32_FIND_DATA structure, which includes the file's attributes, size, and timestamp data alongside the file's name.

os.scandir() wraps these low-level calls and encapsulates the returned data inside os.DirEntry objects. Because the operating system supplies this metadata during the initial directory read, Python does not need to issue subsequent system calls to determine whether an entry is a file, directory, or symlink.

Attribute Caching with os.DirEntry

An os.DirEntry object exposes methods such as is_dir(), is_file(), is_symlink(), and stat().

When you call entry.is_dir() or entry.is_file():

  1. Python checks the cached file type already retrieved from the underlying OS directory read.
  2. If the operating system provided the file type (which is standard on Windows and modern POSIX filesystems like ext4, Btrfs, and APFS), the method returns immediately without a system call.
  3. On Windows, entry.stat() uses the cached WIN32_FIND_DATA attributes, meaning retrieving file size or modification time also avoids an extra system call.
  4. If a system call is ever necessary (e.g., following a symlink or on a rare POSIX filesystem that does not populate d_type), the result is cached within the os.DirEntry instance for subsequent lookups.

Memory and Streaming Efficiency

In addition to avoiding system calls, os.scandir() returns an iterator rather than pre-allocating a complete list in memory. For directories containing millions of files, os.listdir() must allocate memory for the entire list of strings before your program can process the first item. os.scandir() streams os.DirEntry objects on demand, decreasing memory usage and allowing programs to begin processing files immediately.

Because of these low-level advantages, directory traversal with os.scandir() is typically 2 to 3 times faster on POSIX systems and 8 to 20 times faster on Windows systems compared to traditional os.listdir() and os.stat() workflows.
