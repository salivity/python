Python eq vs is: Equality and Identity Explained

In Python, comparing data relies on two fundamental concepts: value equality and object identity. The == operator evaluates equality by invoking an object's __eq__ magic method to determine if two distinct objects hold equivalent values. In contrast, the is keyword checks identity, verifying whether two variables reference the exact same memory location. Understanding the internal mechanics of __eq__ versus is is critical for writing bug-free code and avoiding unexpected behavior when comparing objects.

Object Identity: The is Keyword

The is keyword compares the memory addresses of two objects. It evaluates to True if and only if both operands point to the exact same object in memory. Under the hood, Python checks the internal pointer of the objects, which corresponds to comparing their memory addresses via the built-in id() function:

a is b  # Equivalent to: id(a) == id(b)

Because is operates at the C-pointer level in CPython, it cannot be overridden or customized by user-defined classes. This makes identity checks exceptionally fast.

The primary use case for is is comparing against singletons, most commonly None:

if result is None:
    # Handle missing value

You should avoid using is to compare literals like integers or strings. While CPython caches small integers (typically from -5 to 256) and interns certain strings—making a is b evaluate to True for these cached values—this is an implementation detail and not guaranteed behavior across different Python implementations or execution contexts.

Value Equality: The __eq__ Method

The == operator evaluates whether two objects represent the same data, regardless of where they reside in memory. When you execute a == b, Python translates this expression into a call to the left operand's __eq__ dunder method:

a.__eq__(b)

If the left operand's __eq__ method returns NotImplemented, Python automatically attempts the reverse operation by calling the right operand's method: b.__eq__(a). If neither object implements a comparison that returns a boolean, Python falls back to identity comparison (is).

By default, user-defined classes inherit object.__eq__, which defaults to identity comparison. You can override __eq__ to implement custom equality logic:

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        if not isinstance(other, Point):
            return NotImplemented
        return self.x == other.x and self.y == other.y

p1 = Point(1, 2)
p2 = Point(1, 2)

print(p1 == p2)  # True (same values via __eq__)
print(p1 is p2)  # False (distinct memory locations)

Practical Comparison

Consider how standard mutable collections behave:

list1 = [1, 2, 3]
list2 = [1, 2, 3]
list3 = list1

# Comparing list1 and list2
print(list1 == list2)  # True: Both contain equivalent elements
print(list1 is list2)  # False: Distinct list instances in memory

# Comparing list1 and list3
print(list1 == list3)  # True: Both contain equivalent elements
print(list1 is list3)  # True: Both point to the exact same list instance

Modifying list1 will also alter list3 because they share an identity, but list2 remains unaffected.

Key Rules of Thumb

  • Use == when you care about the content, structure, or numeric equivalence of data (e.g., comparing numbers, strings, dictionaries, or custom data structures).
  • Use is only when you need to verify that two references point to the exact same instance in memory, most notably when checking for None, True, False, or custom sentinel objects.
