Python In-Place Operator Overloading with iadd

In Python, in-place operator overloading allows developers to define custom behavior for augmented assignment expressions such as += through the special method __iadd__. This article explains how Python evaluates augmented assignments, how __iadd__ differentiates between mutable and immutable data structures, the fallback mechanism to standard addition, and the mandatory return requirements for custom implementations.

How Augmented Assignment Works

When Python encounters an expression like x += y, it does not immediately evaluate it as x = x + y. Instead, it first checks if the object referenced by x defines an in-place addition method, __iadd__.

The underlying bytecode execution treats the statement conceptually as:

x = x.__iadd__(y)

Because of this assignment step, the __iadd__ method must return an object—almost always self when mutating an existing instance—which is then rebound to the target variable name.

The Fallback to __add__

If a class does not implement __iadd__, or if __iadd__ returns the singleton NotImplemented, Python falls back to standard binary addition. The evaluation order proceeds as follows:

  1. Look for x.__iadd__(y). If implemented and not returning NotImplemented, rebind x to the returned result.
  2. If __iadd__ is missing or returns NotImplemented, attempt x.__add__(y).
  3. If __add__ is not implemented or returns NotImplemented, attempt the reflected addition method on the right operand: y.__radd__(x).
  4. If a valid result is returned from __add__ or __radd__, rebind x to that new object.
  5. If all options return NotImplemented, Python raises a TypeError.

This fallback ensures that any type supporting standard addition (+) automatically supports augmented addition (+=) without requiring explicit implementation of __iadd__.

Mutability and In-Place Behavior

The primary purpose of __iadd__ is performance optimization through mutation.

Mutable Objects

For mutable objects like lists, creating a brand-new object on every concatenation is computationally expensive. Python’s list implements __iadd__ to extend the existing list in memory rather than allocating a new one:

a = [1, 2]
b = a
a += [3]

print(a)  # [1, 2, 3]
print(b)  # [1, 2, 3] (b reflects the mutation because 'a' and 'b' share identity)
print(a is b)  # True

Immutable Objects

Immutable objects such as integers, strings, and tuples cannot be modified in place. These types do not implement mutating behavior in __iadd__. When executing += on an immutable object, Python either relies on the fallback to __add__ or returns a new instance from __iadd__:

x = 10
y = x
x += 5

print(x)  # 15
print(y)  # 10
print(x is y)  # False (a new integer object was assigned to x)

Implementing __iadd__ in Custom Classes

When defining __iadd__ in a custom class, two rules must be observed:

  1. Mutate the internal state of the current instance rather than creating a new one.
  2. Return self at the end of the method. Forgetting to return self causes the variable to be rebound to None, since Python assigns the result of the method call back to the variable.
class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __add__(self, other):
        """Standard addition: returns a new instance."""
        if isinstance(other, Vector):
            return Vector(self.x + other.x, self.y + other.y)
        return NotImplemented

    def __iadd__(self, other):
        """In-place addition: mutates self and returns self."""
        if isinstance(other, Vector):
            self.x += other.x
            self.y += other.y
            return self
        return NotImplemented

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

If v = Vector(1, 2), executing v += Vector(3, 4) updates the existing v coordinates to (4, 6) and maintains its original memory address.
