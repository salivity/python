Python async def vs Generator-Based Coroutines

Python’s asynchronous programming landscape underwent a major architectural shift when native coroutines (async def) replaced generator-based coroutines (@asyncio.coroutine and yield from). While both mechanisms enable cooperative multitasking by pausing and resuming execution, they differ fundamentally in Python's type system, internal protocols, execution safety, and syntax. Understanding these differences clarifies why generator coroutines were completely removed in Python 3.11 and how native coroutines provide robust, first-class asynchronous support.

Distinct Protocols and Internal Types

The primary fundamental difference lies in Python’s internal type system.

Generator-based coroutines are generators. They rely on the generator protocol:

  • They are instances of types.GeneratorType.
  • They pause execution using the yield or yield from expressions.
  • They implement __iter__() and __next__() alongside generator-specific control methods like .send(), .throw(), and .close().

Native coroutines, introduced via async def, are entirely distinct types:

  • They are instances of types.CoroutineType.
  • They pause execution using the await expression.
  • They implement the __await__() method, deliberately separating asynchronous suspension from standard iteration.

Because native coroutines do not implement __next__() or __iter__(), they cannot be iterated over like data streams. This separation eliminates the conceptual blurring between producing values (iteration) and yielding control to an event loop (concurrency).

Syntax and Ambiguity

Before Python 3.5, asynchronous code relied on the @asyncio.coroutine decorator wrapping a standard generator function:

# Legacy generator-based coroutine
import asyncio

@asyncio.coroutine
def fetch_data():
    yield from asyncio.sleep(1)
    return "data"

Because this syntax relied on yield from, it was impossible to determine at a glance whether a function was an asynchronous task or a lazy sequence producer without inspecting decorators and context.

Native coroutines introduce dedicated keywords:

# Native coroutine
import asyncio

async def fetch_data():
    await asyncio.sleep(1)
    return "data"

The async and await keywords make the developer's intent explicit to both the compiler and static analysis tools.

Error Handling and Debugging Safety

Generator-based coroutines suffered from silent failures. If a developer called a generator coroutine without using yield from, the function simply returned a generator object that sat unexecuted. The interpreter could not identify whether the omission was a bug or intentional deferred execution.

Native coroutines introduce compiler-level safeguards:

  1. Unawaited Coroutine Warnings: If an async def function is called without being awaited or scheduled on an event loop, Python raises a RuntimeWarning: coroutine '...' was never awaited when the object is garbage-collected.
  2. Static Type Checking: Type checkers (such as Mypy and Pyright) can strictly differentiate between Coroutine[Any, Any, T] and Generator[YieldType, SendType, ReturnType], catching control-flow bugs before runtime.

Asynchronous Context Managers and Iterators

Native coroutines expand Python's grammar to support asynchronous iteration and resource management, which generator-based coroutines could not natively support:

  • Asynchronous Context Managers: Managed via async with, powered by the __aenter__() and __aexit__() methods.
  • Asynchronous Iterators: Managed via async for, powered by the __aiter__() and __anext__() methods.

These structures allow non-blocking resource acquisition (such as database connections) and streaming data over network sockets while maintaining readable context management patterns.

Performance and Deprecation

At the runtime level, async def coroutines benefit from C-level optimizations in CPython. Native coroutines bypass the overhead of standard generator frame evaluation when executing await chains, leading to faster context switching in modern event loops.

Generator-based coroutines were formally deprecated in Python 3.8 and removed entirely in Python 3.11. async def and await represent the modern, performant, and permanently established foundation of Python concurrency.
