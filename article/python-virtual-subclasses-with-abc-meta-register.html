Python Virtual Subclasses with ABCMeta.register

Python's abc.ABCMeta.register() enables "virtual subclassing," a mechanism allowing a class to be recognized as a subclass of an Abstract Base Class (ABC) without explicitly inheriting from it. This article explains how ABCMeta.register() achieves this decoupling by leveraging internal reference registries and metaclass hooks (__subclasscheck__ and __instancecheck__), all while keeping the target class's Method Resolution Order (MRO) completely untouched.

The Purpose of Virtual Subclasses

Standard inheritance couples interface declaration with implementation inheritance. When a class inherits from a parent, the parent enters the child's __mro__, granting access to attributes and methods.

Virtual subclassing breaks this coupling. It allows a class to satisfy interface checks—such as isinstance() and issubclass()—to support structural subtyping and duck typing without forcing the class to inherit state, methods, or base class constraints.

from abc import ABC

class PluginInterface(ABC):
    pass

class CustomPlugin:
    pass

# Register CustomPlugin as a virtual subclass
PluginInterface.register(CustomPlugin)

print(issubclass(CustomPlugin, PluginInterface))  # True
print(isinstance(CustomPlugin(), PluginInterface)) # True

Internal Registration Storage

When ABCMeta.register(subclass) is invoked, it does not modify the target class's attributes, base tuple (__bases__), or MRO (__mro__).

Instead, the metaclass updates an internal registry maintained on the ABC itself. In modern Python implementations, this is managed via an internal C-extension module (_abc):

  1. Registry Set: The ABC maintains a set of weak references to registered virtual subclasses (historically _abc_registry).
  2. Cache Sets: To ensure high performance, the ABC also maintains caches for positive matches (_abc_cache) and negative matches (_abc_negative_cache).

Because the registry relies on weak references, registering a class does not prevent it from being garbage collected if it goes out of scope.

The Inspection Hooks: __subclasscheck__ and __instancecheck__

Python's built-in functions issubclass() and isinstance() do not perform simple attribute lookups. Instead, they check for custom metaclass hooks:

  • issubclass(C, B) calls type(B).__subclasscheck__(B, C).
  • isinstance(obj, B) calls type(B).__instancecheck__(B, obj).

abc.ABCMeta overrides both methods to define custom resolution logic:

  1. Fast-path check: Python first checks if the candidate class is directly in the inheritance tree via standard MRO resolution.
  2. Cache lookup: It checks whether the candidate class is already present in _abc_cache.
  3. Registry traversal: If not cached, ABCMeta.__subclasscheck__ iterates through the classes in the registry. If the candidate class is either a registered class or a subclass of a registered class, the check returns True.
  4. Caching: Successful lookups are stored in _abc_cache, while failed lookups are stored in _abc_negative_cache to speed up subsequent queries.

Key Architectural Implications

  • Unchanged MRO: Because the ABC is absent from the virtual subclass's __mro__, super() calls inside the virtual subclass will never resolve methods from the ABC.
  • No Automatic Method Inheritance: The virtual subclass receives no concrete methods or mixin logic defined on the ABC.
  • No Instantiation Enforcement: Unlike nominal subclasses, Python does not verify whether a virtual subclass implements @abstractmethod declarations upon instantiation. Enforcement relies entirely on the developer to uphold the expected interface.
