How Python Resolves Relative Imports with Dots

This article explains how Python uses leading dots to resolve explicit relative imports within packages. You will learn the mechanics behind syntax like from . import sibling, how Python relies on the __name__ and __package__ attributes to traverse package hierarchies, and why running modules directly often breaks relative import resolution.

The Syntax of Leading Dots

Python uses dots to specify relative positioning within the package hierarchy:

  • Single dot (.): Represents the current package directory where the importing module resides.
  • Double dots (..): Represents the parent package (one level up).
  • Three dots (...): Represents the grandparent package (two levels up), with each additional dot moving one level higher.

For example, consider this package structure:

my_package/
│
├── __init__.py
├── sibling.py
├── module_a.py
└── subpackage/
    ├── __init__.py
    └── module_b.py

Inside module_a.py, importing sibling can be done using:

from . import sibling
from .sibling import some_function

Inside subpackage/module_b.py, referencing sibling requires stepping up one directory to my_package:

from .. import sibling

How the Resolution Mechanism Works

Python’s import system does not inspect the physical filesystem path when resolving relative imports. Instead, it relies entirely on the module’s metadata attributes: __name__ and __package__.

  1. Identifying the Current Anchor: When a module is loaded as part of a package, Python populates __package__. For example, if Python loads my_package.subpackage.module_b, its __name__ is set to "my_package.subpackage.module_b", and its __package__ is set to "my_package.subpackage".
  2. Calculating the Target Path:
    • A single dot (.) anchors the resolution to the value of __package__ ("my_package.subpackage").
    • Each subsequent dot strips the rightmost component from the package string. Two dots (..) removes .subpackage, leaving "my_package".
  3. Translating to an Absolute Import: Python appends the imported name to the derived package path. from .. import sibling is internally transformed into an absolute lookup for my_package.sibling.
  4. Loading via sys.modules: Python checks sys.modules for the resolved absolute name. If the module is not already loaded, it uses standard import loaders to locate and execute the file.

Why Relative Imports Fail in __main__

A frequent issue with relative imports is the following error:

ImportError: attempted relative import with no known parent package

This occurs when a file containing a relative import is executed directly as a script (e.g., python my_package/module_a.py).

When a script is run directly, Python assigns its __name__ attribute to "__main__" and sets __package__ to None (or an empty string). Because the module no longer knows where it sits in the package hierarchy, the import system cannot calculate what the leading dots refer to.

To resolve relative imports correctly during execution, the code must be run as a module from outside the package directory using the -m switch:

python -m my_package.module_a

This execution method ensures that Python initializes __package__ properly, allowing the relative dot notation to resolve as intended.
