Python Subgenerator Return Values Explained

When a Python subgenerator completes its execution using a return statement, the returned value becomes the evaluation result of the yield from expression in the delegating generator. Under the hood, Python accomplishes this by raising a StopIteration exception where the returned value is stored in the exception's value attribute, which the yield from syntax automatically intercepts and extracts.

How yield from Captures Return Values

In Python, generators can yield intermediate values to the caller and optionally return a final value upon termination. When a delegating generator calls a subgenerator using yield from, it establishes a bidirectional pipe. The caller receives all values yielded by the subgenerator. Once the subgenerator finishes by executing a return <value> statement, the delegation finishes, and the value is assigned directly to the variable receiving the yield from expression.

def subgenerator():
    yield "A"
    yield "B"
    return "Finished successfully"

def delegator():
    result = yield from subgenerator()
    print(f"Result captured in delegator: {result}")

for item in delegator():
    print(f"Yielded: {item}")

Output:

Yielded: A
Yielded: B
Result captured in delegator: Finished successfully

If the subgenerator finishes without an explicit return statement, it implicitly returns None, making None the resulting value of the yield from expression.

The Underlying Mechanism: StopIteration.value

Understanding how this works manually highlights why yield from behaves the way it does. When a generator function returns, Python raises a StopIteration exception to signal the end of the iteration sequence. The argument passed to return is placed inside the value attribute of the exception instance.

When driving a generator manually with next():

gen = subgenerator()
print(next(gen))  # Prints 'A'
print(next(gen))  # Prints 'B'

try:
    next(gen)
except StopIteration as exc:
    print(exc.value)  # Prints 'Finished successfully'

The yield from construct automates this manual handling. It intercepts the StopIteration, extracts exc.value, and provides that value as the outcome of the expression, allowing clean composition of coroutines and nested generators.
