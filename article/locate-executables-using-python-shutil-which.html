Locate Executables Using Python shutil.which

The shutil.which() function in Python identifies the absolute file system path of a specified executable by scanning the directories listed in the system's PATH environment variable. Introduced in Python 3.3, it provides a native, cross-platform implementation of the standard Unix which command, allowing developers to programmatically verify whether an external tool is installed and accessible before attempting to invoke it.

Core Functionality

When working with external commands or child processes, relying on hardcoded paths can cause cross-platform compatibility failures. shutil.which() solves this by querying the environment dynamically.

import shutil

# Locate an executable
path = shutil.which("git")
print(path)
# Output on Linux/macOS: /usr/bin/git
# Output on Windows: C:\Program Files\Git\cmd\git.EXE

If the command is found, shutil.which() returns a string containing the complete path to the binary. If the command does not exist in any searched directory or lacks execution permissions, it returns None.

How It Operates

The function accepts three arguments: cmd, mode, and path.

  • cmd: The name of the binary to locate (e.g., "python", "ffmpeg", "curl").
  • mode: The permission flags passed to os.access(). By default, this is os.F_OK | os.X_OK, meaning the function checks for both the file's existence and its executable permission.
  • path: The lookup path to search. By default, it reads the current environment's PATH string via os.environ.get("PATH"). A custom path string can be supplied if a search outside the default system path is needed.

Cross-Platform Handling and Windows PATHEXT

On POSIX-compliant systems (Linux and macOS), shutil.which() evaluates exact file names matching executable permissions.

On Windows, the function automatically handles extension resolution. Windows executables often rely on extensions like .exe, .bat, or .cmd. shutil.which() consults the PATHEXT environment variable, ensuring that querying shutil.which("python") matches python.exe without requiring explicit extension definitions. Additionally, the current working directory is automatically checked on Windows before the rest of PATH, mirroring standard operating system behavior.

Practical Application: Safe Subprocess Execution

The most common use case for shutil.which() is defensive programming prior to calling subprocess.run() or subprocess.Popen().

import shutil
import subprocess

tool_name = "ffmpeg"
executable_path = shutil.which(tool_name)

if executable_path is None:
    raise FileNotFoundError(f"Required binary '{tool_name}' is not installed or not on PATH.")

# Safe to proceed with execution
subprocess.run([executable_path, "-version"], check=True)

By confirming the binary's presence beforehand, applications avoid uncaught FileNotFoundError exceptions and can provide informative error messages or fallback behaviors when dependencies are missing.
