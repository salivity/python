Why Raise StopIteration in Python's next

In Python, raising a StopIteration exception inside an iterator’s __next__ method is the standard mechanism to signal that the iteration sequence has finished. This article explains the role of StopIteration within Python's iterator protocol, demonstrates how built-in constructs like for loops handle it seamlessly, and clarifies why an exception is used instead of a sentinel value.

The Iterator Protocol

Python defines iteration through the iterator protocol, which relies on two methods: __iter__() and __next__(). While __iter__() returns the iterator object itself, __next__() is responsible for returning the subsequent value in the sequence on each call. Because an iterator cannot continue indefinitely unless specifically designed as an infinite sequence, it must have a clear, unambiguous way to notify the caller that no more elements are available. Raising StopIteration fulfills this requirement.

Clear Distinction Between Data and Termination

Some programming languages use sentinel values, such as null or -1, to signal the end of a sequence. In Python, an iterator can legitimately contain any object, including None, False, or empty data structures. Using an exception like StopIteration cleanly separates the transmission of data from the control flow. If __next__() returned None to indicate completion, an iterator over a list containing None values (such as [1, None, 2]) would prematurely terminate. StopIteration ensures that any valid Python object can be yielded without ambiguity.

How Built-in Constructs Handle StopIteration

Built-in looping mechanisms, such as for loops, list comprehensions, and functions like map() or zip(), inherently anticipate StopIteration. When you write a for loop, Python calls __next__() behind the scenes on each iteration and wraps the call in an implicit try...except StopIteration block:

class CountDown:
    def __init__(self, start):
        self.current = start

    def __iter__(self):
        return self

    def __next__(self):
        if self.current <= 0:
            raise StopIteration
        val = self.current
        self.current -= 1
        return val

for number in CountDown(3):
    print(number)

Output:

3
2
1

When self.current reaches 0, the StopIteration exception is raised. The for loop catches this exception immediately and exits cleanly without crashing or displaying a traceback.

Manual Iteration with the next() Built-in

If you iterate through an object manually using the next() function, the raised StopIteration will bubble up unless explicitly handled:

counter = CountDown(1)
print(next(counter))  # Outputs: 1
print(next(counter))  # Raises StopIteration

To prevent an unhandled exception when calling next() manually, you can provide a default fallback value as the second argument: next(counter, "Done"). When provided, next() intercepts the StopIteration and returns the default value instead.
