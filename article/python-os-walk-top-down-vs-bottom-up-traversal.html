Python os.walk: Top-Down vs Bottom-Up Traversal

Python's os.walk() function is an essential tool for recursive directory navigation, yielding a three-item tuple at each step of the traversal. This article explains the exact data structure os.walk() yields and details the critical behavioral differences between traversing a file system tree top-down versus bottom-up using the topdown parameter.

The Structure of What os.walk() Yields

Regardless of the traversal direction, every iteration of os.walk() yields a 3-tuple:

(dirpath, dirnames, filenames)
  • dirpath (string): The path to the directory currently being inspected.
  • dirnames (list): A list of names of all subdirectories found directly inside dirpath.
  • filenames (list): A list of names of all non-directory files found directly inside dirpath.

Neither dirnames nor filenames contain full path strings; they only contain the names of the items. To access the full path to a file or folder, combine them with dirpath using os.path.join(dirpath, name).

Top-Down Traversal (topdown=True)

Top-down is the default behavior when calling os.walk(path) or explicitly setting os.walk(path, topdown=True).

Yield Order

In a top-down traversal (pre-order traversal), os.walk() yields the parent directory before yielding any of its subdirectories. It visits the starting root folder first, lists its contents, and then dives deeper into the nested folders.

Dynamic Directory Pruning

Because the parent is evaluated first, you can modify the dirnames list in-place to control which subdirectories are visited next:

for dirpath, dirnames, filenames in os.walk(root, topdown=True):
    # Exclude unwanted directories from being traversed
    dirnames[:] = [d for d in dirnames if d != '.git' and d != '__pycache__']

Using slice assignment (dirnames[:] = ...) updates the list in place, telling os.walk() to skip the excluded folders entirely, saving both memory and processing time.

Bottom-Up Traversal (topdown=False)

When passing topdown=False, os.walk() switches to a post-order traversal.

Yield Order

In a bottom-up traversal, os.walk() yields all subdirectories before yielding their containing parent directory. The traversal reaches the deepest levels of the directory hierarchy first and works its way back up to the starting root.

Pruning Behavior

Modifying the dirnames list in bottom-up mode has no effect on the traversal. By the time os.walk() yields the tuple for a directory, it has already generated the subdirectories and traversed them.

Primary Use Case: Recursive Deletion

Bottom-up traversal is essential when performing actions that require child elements to be processed or deleted before their parents. For example, removing files and deleting empty directories requires the leaf nodes to be cleared before the parent directory can be removed:

for dirpath, dirnames, filenames in os.walk(root, topdown=False):
    for f in filenames:
        os.remove(os.path.join(dirpath, f))
    for d in dirnames:
        os.rmdir(os.path.join(dirpath, d))

Summary of Differences

  • Yield Sequence: topdown=True yields parent folders before their contents; topdown=False yields leaf subdirectories before the parent folders.
  • Tuple Contents: Both modes yield (dirpath, dirnames, filenames).
  • Pruning: Modifying dirnames in-place works only with topdown=True.
  • Application: Use top-down when searching or filtering directory paths; use bottom-up when deleting, moving, or calculating bottom-up metrics (such as aggregated folder sizes).
