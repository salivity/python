What Does Python enter Return in a With Block?

In Python, context managers simplify resource management through the with statement, which relies primarily on the __enter__ and __exit__ dunder methods. This article explains precisely what the __enter__ method returns upon entering a context block, how this value binds to the optional as clause, and how developers can control this behavior in custom classes.

The Return Value of __enter__

When Python executes a with statement, it immediately evaluates the context expression and calls its __enter__ method. The value returned by __enter__ is the exact object assigned to the variable following the as keyword.

Syntax representation:

with context_manager as target:
    # 'target' holds the value returned by context_manager.__enter__()
    pass

If the with statement does not include an as target, the __enter__ method still executes, but its return value is discarded.

Common Return Scenarios

Python imposes no strict restriction on what __enter__ must return. Depending on the design of the context manager, it typically falls into one of three patterns:

1. Returning self

The most common implementation returns the instance of the context manager itself. This pattern is ideal when the object managing the context is also the resource being manipulated inside the block.

class DatabaseConnection:
    def __enter__(self):
        self.connect()
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        self.close()

with DatabaseConnection() as db:
    # 'db' is the instance of DatabaseConnection
    db.query("SELECT 1")

Python’s built-in open() function follows this pattern: __enter__ returns the file object itself.

2. Returning a Separate Object or Data

A context manager can return a completely different object, such as a managed resource, a client wrapper, or data extracted during setup.

class TemporaryDirectory:
    def __enter__(self):
        self.path = "/tmp/generated_folder"
        return self.path  # Returns a string path, not the class instance

    def __exit__(self, exc_type, exc_val, exc_tb):
        # Cleanup directory
        pass

with TemporaryDirectory() as dir_path:
    # 'dir_path' is a string
    print(dir_path)

3. Returning None

If an __enter__ method does not explicitly execute a return statement, it returns None by default. This is standard practice when a context manager modifies global state or runs setup logic that does not produce a distinct object.

import sys

class SuppressOutput:
    def __enter__(self):
        self._stdout = sys.stdout
        sys.stdout = None
        # Implicitly returns None

    def __exit__(self, exc_type, exc_val, exc_tb):
        sys.stdout = self._stdout

with SuppressOutput():
    # No 'as' target is needed because nothing useful is returned
    pass

Summary

The __enter__ method returns whatever value the developer defines via its return statement. That returned value is then bound to the variable specified in the as clause of the with statement, defaulting to None if no return value is specified.
