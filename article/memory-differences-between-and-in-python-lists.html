Memory Differences Between += and + in Python Lists

In Python, extending a list using the in-place addition operator (+=) differs significantly in memory management from reassigning it via concatenation (list = list + [...]). While both expressions yield a list containing the combined elements, += modifies the existing list object directly in memory, whereas list = list + [...] creates an entirely new list object and rebinds the variable name to it. This distinction affects memory allocation overhead, peak memory consumption, and reference behavior across variables.

In-Place Extension with +=

When you apply += to a list, Python invokes the object's __iadd__() method. For mutable sequences like lists, __iadd__() behaves identically to the .extend() method.

a = [1, 2, 3]
print(id(a))  # e.g., 1402384920

a += [4, 5]
print(id(a))  # 1402384920 (Same memory address)

The memory address of the list remains unchanged. CPython manages list storage using an internal array of pointers that is dynamically resized. When elements are added via +=, Python attempts to append them to the existing allocated buffer. If the buffer is full, it reallocates the array with over-allocation padding, but the outer list container object remains at the exact same memory address.

Because the underlying object is mutated in place, any other variables referencing the same list will immediately reflect the changes:

x = [1, 2]
y = x
x += [3]

print(y)  # Outputs: [1, 2, 3]

New Object Creation with list = list + [...]

When you use the binary addition operator (+), Python calls the __add__() method. This method cannot modify the operands; instead, it allocates an entirely new list object in memory capable of holding the combined elements from both the left and right operands.

a = [1, 2, 3]
print(id(a))  # e.g., 1402384920

a = a + [4, 5]
print(id(a))  # e.g., 1402385112 (New memory address)

In terms of memory mechanics:

  1. Python creates a new list in a separate memory block.
  2. It copies the item references from the original list into the new list.
  3. It copies the item references from the appended list into the new list.
  4. The variable a is rebound to the new list object.
  5. If no other references to the original list exist, its reference count drops to zero, marking it for deallocation by Python's garbage collector.

Because a new object is created, shared references are broken:

x = [1, 2]
y = x
x = x + [3]

print(y)  # Outputs: [1, 2] (Unaltered)
print(x)  # Outputs: [1, 2, 3]

Performance and Memory Footprint

The memory overhead of list = list + [...] is substantially higher than +=:

  • Peak Memory Usage: Evaluating list = list + [...] requires sufficient memory to hold the original list, the list being appended, and the newly allocated combined list simultaneously before the original can be garbage-collected. In contrast, += only requires extra memory for the incoming elements and potential buffer resizing.
  • Time Complexity: Extending a list of size \(N\) with \(K\) elements via += runs in amortized \(O(K)\) time because only the new elements need to be appended. Concatenating via + runs in \(O(N + K)\) time because all \(N\) existing elements must be copied into the new memory buffer alongside the \(K\) new elements. Repeatedly using list = list + [...] inside loops can rapidly cause quadratic \(O(N^2)\) memory copying and significant performance degradation.
