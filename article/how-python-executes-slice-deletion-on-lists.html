How Python Executes Slice Deletion on Lists

When you run del my_list[start:stop:step], Python removes multiple elements from a mutable sequence in a single, in-place operation. This article explains how Python translates the slice syntax into an internal call, resolves bounds and step sizes, shifts the remaining elements in memory, and reallocates the underlying array to maintain contiguous storage.

1. Translation to the Data Model

At the bytecode level, the statement del my_list[start:stop:step] compiles to the DELETE_SUBSCR opcode. The Python virtual machine evaluates this by delegating the deletion to the object's special method:

my_list.__delitem__(slice(start, stop, step))

For built-in mutable sequences like list, the operation is handled in CPython by the C-level function list_ass_subscript.

2. Normalizing the Slice (slice.indices)

Before deleting any data, Python must determine which indices are targeted. A sequence's length is finite, but slice parameters can be None, negative, or out of bounds.

CPython normalizes the slice using the equivalent of the C API function PySlice_Unpack (or the Python-level slice.indices(len(my_list))). This step computes four concrete values:

  • start: The clamped, positive starting index.
  • stop: The clamped, positive stopping index.
  • step: The stride direction and distance (must not be 0).
  • slicelength: The exact number of items targeted for removal.

If slicelength evaluates to 0, the operation terminates immediately without altering the list.

3. Memory Layout and Execution Paths

Python lists are implemented as dynamically sized arrays of pointers (PyObject*). Because an array must remain contiguous in memory, removing elements requires two actions: releasing references to the removed items and shifting the retained items to close the gaps.

CPython handles the execution via two distinct paths depending on the step value.

Contiguous Slices (step == 1 or omitted)

When step == 1, all targeted elements sit next to each other. CPython optimizes this via the internal list_ass_slice routine:

  1. Decref elements: Python decrements the reference count of every PyObject* in the target range [start:stop]. If an object's reference count drops to zero, it is deallocated.
  2. Block memory shift: The remaining tail of the list (elements from stop to the end) is shifted left to fill the vacant index range starting at start. This is executed with a low-level memmove call, which is highly efficient.
  3. Update metadata: The list's size attribute is reduced by slicelength.

Extended Slices (step != 1)

When step is greater than 1 or negative, the items to be deleted are scattered across the array rather than clustered in a single block:

  1. Targeted traversal: CPython calculates each index to remove based on start + i * step.
  2. In-place compaction: Instead of shifting memory repeatedly for every individual deleted item, Python walks through the array in a single pass. Surviving items are moved forward into their new contiguous positions, and targeted items have their reference counts decremented.
  3. Update metadata: The sequence length is updated once the single compaction pass completes.

4. Memory Reallocation (list_resize)

Deleting items leaves the underlying memory buffer larger than necessary. To avoid excessive memory waste, CPython invokes its internal resizing function, list_resize.

  • Overallocation buffer: Python lists intentionally allocate extra capacity to allow \(O(1)\) amortized appends.
  • Shrinking threshold: If the new size falls below roughly half of the currently allocated capacity, CPython calls realloc to shrink the allocated memory block and return the unused memory to the system allocator.

5. Time and Space Complexity

  • Time Complexity: \(O(N)\), where \(N\) is the total number of elements in the list. Even if deleting only a few elements, Python must shift all subsequent elements to maintain a contiguous array.
  • Space Complexity: \(O(1)\) auxiliary space, as all index calculations, item deallocations, and pointer moves occur directly within the existing memory allocation.
