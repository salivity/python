How the Python Generator close() Method Works

Calling the .close() method on an active Python generator cleanly terminates its execution by injecting a GeneratorExit exception at the point where the generator was suspended. This article explains the internal mechanics of .close(), how it triggers cleanup routines, what happens if the generator tries to ignore the shutdown, and how the generator behaves on subsequent calls.

Raising the GeneratorExit Exception

When a generator is paused at a yield expression and .close() is called, Python immediately resumes the generator by raising a GeneratorExit exception at that exact suspension point.

Under normal circumstances, the generator does not catch this exception explicitly, or it catches it only to run cleanup operations. The exception bubbles out of the generator function, Python catches it internally, and the .close() call returns None to the caller. The generator's state is then set to GEN_CLOSED.

Executing Cleanup Code

The primary purpose of .close() is to allow generators to release resources safely. When GeneratorExit is raised inside the generator, any active try...finally blocks execute:

def resource_reader():
    try:
        print("Acquiring resource")
        yield "data"
    finally:
        print("Releasing resource")

gen = resource_reader()
next(gen)          # Outputs: Acquiring resource
gen.close()        # Outputs: Releasing resource

Once the finally block finishes, execution ceases, and control returns to the code that called .close().

The Restriction Against Yielding Values

A generator undergoing closure is forbidden from yielding any further values. If a generator catches GeneratorExit and attempts to execute another yield statement, Python raises a RuntimeError:

def invalid_generator():
    try:
        yield 1
    except GeneratorExit:
        yield 2  # Prohibited!

gen = invalid_generator()
next(gen)
gen.close()  # Raises: RuntimeError: generator ignored GeneratorExit

If the generator raises any other standard exception during termination (such as a ValueError or an error inside a finally block), that exception propagates up to the caller of .close().

Behavior on Finished or Closed Generators

If .close() is called on a generator that has already completed its execution or has already been closed, the method returns immediately and does nothing.

However, once a generator is closed, any subsequent attempt to advance it using next() or .send() will immediately raise a StopIteration exception, as the generator is permanently exhausted.
