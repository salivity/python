How Python Binds Default Parameter Values Once

In Python, default parameter values are evaluated and bound exactly once when the function definition is executed, rather than dynamically each time the function is called. This design choice stems from how the Python compiler and runtime treat the def keyword as an executable statement rather than a compile-time declaration. This article explains the underlying runtime mechanics, how the interpreter stores default arguments in function objects, and how this architecture dictates Python's parameter resolution.

The Execution of the def Statement

In Python, def is an executable statement. When the Python runtime encounters a def block in a module or scope, it executes that statement immediately. During this execution, the interpreter does three specific things:

  1. It compiles the function body into a code object (<code object>).
  2. It evaluates all expressions provided as default parameter values in the surrounding scope.
  3. It instantiates a new function object (types.FunctionType), binding the compiled code object and the evaluated default values together.

Because expressions defining default values are evaluated during this step, they are only calculated once. The runtime does not retain the syntax or expression used to produce the default value; it retains only the resulting object reference.

Storage in the __defaults__ Attribute

Once evaluated, Python stores positional default values inside a tuple assigned to the function object's __defaults__ attribute. For keyword-only parameters, values are stored in a dictionary under __kwdefaults__.

Consider the following example:

def append_to(item, target_list=[]):
    target_list.append(item)
    return target_list

When this definition is parsed:

  • The empty list expression [] is evaluated, creating a list object in memory.
  • Python binds this object reference to append_to.__defaults__, which becomes ([],).

You can inspect this directly at runtime:

print(append_to.__defaults__)
# Output: ([],)

The function body contains instructions to access __defaults__, but it contains no instructions to reconstruct the list.

Call-Time Parameter Resolution

When append_to("a") is called, the interpreter constructs a local execution frame:

  1. It maps the passed argument "a" to the parameter item.
  2. It checks whether an argument was passed for target_list.
  3. Seeing no argument provided, the interpreter retrieves the corresponding reference from append_to.__defaults__ and assigns it to the local variable name target_list within that call's frame.

Because __defaults__ holds a reference to the exact same list instance created at definition time, mutating target_list modifies the object referenced inside __defaults__:

append_to("a")
print(append_to.__defaults__)
# Output: (['a'],)

append_to("b")
print(append_to.__defaults__)
# Output: (['a', 'b'],)

Subsequent calls without an explicit argument continue to draw the same mutated object reference from the tuple.

Why Python Enforces Single Binding

This behavior is enforced primarily for runtime performance and design consistency:

  • Performance Optimization: Evaluating default expressions on every function call would introduce substantial overhead, requiring the interpreter to evaluate arbitrary expressions repeatedly even when standard inputs are used.
  • Scope Consistency: If defaults were evaluated at call time, Python would need complex scoping rules to determine whether expressions should resolve in the caller's scope, the defining module's scope, or the function's local scope. Binding at definition time guarantees that defaults are consistently evaluated in the enclosing scope where the function was created.

The Idiomatic Workaround for Mutable Defaults

To achieve dynamic evaluation at call time, the standard Python pattern is to use None as a sentinel value in the function signature, instantiating the mutable object inside the function body:

def append_to(item, target_list=None):
    if target_list is None:
        target_list = []
    target_list.append(item)
    return target_list

In this pattern, append_to.__defaults__ holds (None,). Because the empty list is instantiated inside the function body, the bytecode executing the list creation runs only when the function is explicitly invoked.
