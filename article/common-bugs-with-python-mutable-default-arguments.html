Common Bugs with Python Mutable Default Arguments

Using mutable objects—such as lists, dictionaries, or sets—as default parameter values in Python is one of the most common pitfalls for developers. Because Python evaluates default arguments only once when the function definition is executed rather than at each call, that default object persists across multiple invocations. This behavior leads to subtle, state-retaining bugs where independent function calls inadvertently modify and share the same object, causing data contamination, silent failures, and thread-safety issues.

The Underlying Mechanism: Definition Time vs. Execution Time

In Python, functions are first-class objects. When the Python interpreter defines a function, it evaluates the default arguments and binds them to the function object's __defaults__ attribute.

If the default is an immutable object (such as an integer, string, or tuple), reassigning the variable inside the function binds the variable name to a new object, leaving the default unaffected. However, if the default is mutable (such as list or dict), in-place modifications (append(), update(), item assignment) alter the single existing object stored in __defaults__.

Common Bug 1: Unintended Accumulation in Lists

The most frequent bug occurs when a list is used as an accumulator or container with an empty list [] as the default value:

def add_item(item, target_list=[]):
    target_list.append(item)
    return target_list

print(add_item("Apple"))   # Output: ['Apple']
print(add_item("Banana"))  # Output: ['Apple', 'Banana'] - Expected: ['Banana']

In this case, a caller expecting a fresh, independent list on every call instead receives a list contaminated with results from previous calls.

Common Bug 2: Cross-Session Data Leakage in Dictionaries

When a dictionary is used as a default parameter for configuration overrides, metadata, or session contexts, mutations persist across callers:

def create_user_profile(username, metadata={}):
    metadata["username"] = username
    return metadata

user1 = create_user_profile("alice")
user2 = create_user_profile("bob")

print(user1)  # Output: {'username': 'bob'}
print(user2)  # Output: {'username': 'bob'}

Both variables point to the exact same dictionary in memory (user1 is user2 evaluates to True). Modifying one user's profile directly alters the other's, which can cause severe data leakage or security vulnerabilities in web applications.

Common Bug 3: Broken Default Cache or Memoization

Developers sometimes unintentionally use default dictionaries to cache expensive operations:

def fetch_data(key, cache={}):
    if key in cache:
        return cache[key]
    result = expensive_operation(key)
    cache[key] = result
    return result

While this appears to work locally, this pattern creates a hidden global state that cannot be cleared, reconfigured, or garbage-collected without restarting the interpreter process. It also introduces race conditions in multi-threaded environments, as Python's standard mutable structures are not thread-safe for concurrent read-and-write operations.

The Idiomatic Solution: Use None as a Sentinel

The standard, idiomatic way to handle mutable defaults in Python is to use None as the default value, and then initialize the mutable collection inside the function body.

def add_item(item, target_list=None):
    if target_list is None:
        target_list = []
    target_list.append(item)
    return target_list

This guarantees that a new list is instantiated in memory every time the function is called without an explicit argument, ensuring isolation and predictable behavior.
