Format Python Exceptions with traceback.format_exc()

This article explains how Python's built-in traceback.format_exc() function captures and formats exception details programmatically. You will learn the mechanics behind the function, its primary parameters, how it differs from direct-printing alternatives, and practical code examples demonstrating how to capture stack traces as standard strings for logging, storage, or external reporting.

What is traceback.format_exc()?

The traceback module in Python provides a standard interface for extracting, formatting, and printing stack traces. Within this module, traceback.format_exc() reads the current exception information from sys.exc_info() and formats the traceback as a standard Python string (str).

Unlike standard crash reports that automatically write directly to standard error (sys.stderr), format_exc() returns the entire traceback string to your program, allowing you to manipulate, filter, save, or transmit the error details.

Syntax and Parameters

The function signature is defined as follows:

traceback.format_exc(limit=None, chain=True)
  • limit (int, optional): Controls the depth of the stack trace to include. If set to a positive integer, it includes up to limit entries starting from the exception invocation. If omitted or set to None, all entries are included.
  • chain (bool, optional): Defaults to True. Controls whether chained exceptions (created using the raise ... from ... syntax or triggered inside an except or finally clause) are included in the formatted output.

Basic Usage

To use traceback.format_exc(), it must be invoked within the context of an active exception—typically inside an except block. If called outside an exception handler, it returns the string "NoneType: None\n".

import traceback

def divide(a, b):
    return a / b

try:
    divide(10, 0)
except ZeroDivisionError:
    formatted_trace = traceback.format_exc()
    print("Captured exception as string:")
    print(formatted_trace)

Output:

Captured exception as string:
Traceback (most recent call last):
  File "example.py", line 7, in <module>
    divide(10, 0)
  File "example.py", line 4, in divide
    return a / b
ZeroDivisionError: division by zero

format_exc() vs. print_exc()

While both functions generate traceback information, they differ in their return values and destinations:

  • traceback.print_exc(limit=None, file=None, chain=True): Formats and immediately prints the traceback to a file-like stream (defaulting to sys.stderr). It returns None.
  • traceback.format_exc(limit=None, chain=True): Returns the formatted traceback as a str without printing it.

Use format_exc() when you need programmatic access to the output, such as:

  • Storing errors in a relational database or document store.
  • Sending crash alerts through messaging webhooks (e.g., Slack, email, or incident management APIs).
  • Attaching the full trace to custom structured JSON logs.

Controlling Output Depth with the limit Parameter

In applications with deep call stacks, you may want to limit the verbosity of the output to prevent log bloat. Passing an integer to limit truncates the stack trace.

import traceback

def step_one():
    step_two()

def step_two():
    raise ValueError("An intentional error")

try:
    step_one()
except ValueError:
    # Limit traceback to the most recent stack frame
    shallow_trace = traceback.format_exc(limit=1)
    print(shallow_trace)

This output will omit higher-level frames and display only the immediate call site and the exception itself.

Managing Chained Exceptions with the chain Parameter

Python 3 automatically chains exceptions that occur while handling another exception. By default, format_exc() renders all chained contexts:

import traceback

try:
    try:
        raise KeyError("Original problem")
    except KeyError as exc:
        raise RuntimeError("Secondary failure") from exc
except RuntimeError:
    full_chain = traceback.format_exc(chain=True)
    single_chain = traceback.format_exc(chain=False)
  • With chain=True, the string includes the message: "The above exception was the direct cause of the following exception:" followed by both stack traces.
  • With chain=False, the string contains only the RuntimeError trace, hiding the causal KeyError.

Integrating with the logging Module

While traceback.format_exc() is effective for manual string manipulation, Python's standard logging library handles stack traces natively when you use exc_info=True or logger.exception(). However, format_exc() remains useful when feeding pre-formatted text into external collectors or custom log formatting engines:

import logging
import traceback

logger = logging.getLogger("AppLogger")

try:
    items = [1, 2, 3]
    print(items[10])
except IndexError:
    error_details = traceback.format_exc()
    logger.error("Operation failed with traceback:\n%s", error_details)
