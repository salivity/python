Understanding __orig_bases__ in Python Generics

When working with Python's typing system, inspecting a generic subclass at runtime often conceals the exact type arguments used during inheritance due to type erasure. The __orig_bases__ attribute solves this issue by preserving the original generic types specified in the class definition, allowing developers to inspect fully parameterized parent classes. This article explores why standard base inspection fails with generics, how __orig_bases__ retains type arguments, and its practical importance in metaprogramming and runtime validation frameworks.

The Limitation of __bases__

In standard Python introspection, a class's immediate parent classes are inspected using the __bases__ attribute. However, when a class inherits from a parameterized generic type, __bases__ strips away the subscripted type arguments.

Consider the following example:

from typing import Generic, TypeVar

T = TypeVar("T")

class Repository(Generic[T]):
    pass

class UserRepository(Repository[int]):
    pass

print(UserRepository.__bases__)
# Output: (<class '__main__.Repository'>,)

While UserRepository explicitly subclasses Repository[int], UserRepository.__bases__ only reports <class '__main__.Repository'>. The concrete type argument int is discarded in the standard base class tuple.

How __orig_bases__ Solves the Problem

To preserve parameterized base classes for runtime inspection, Python introduced the __orig_bases__ attribute via PEP 560. When a class is created with generic arguments in its inheritance list, Python stores the un-erased type expressions inside __orig_bases__.

Using the same classes defined above:

print(UserRepository.__orig_bases__)
# Output: (__main__.Repository[int],)

The __orig_bases__ attribute retains the generic alias Repository[int]. This ensures the exact type arguments remain accessible even after the class has been constructed.

Extracting Type Arguments at Runtime

Because __orig_bases__ preserves the original typing constructs, you can combine it with functions from the typing module—such as get_origin() and get_args()—to dynamically analyze generic hierarchies:

from typing import get_args, get_origin

for base in UserRepository.__orig_bases__:
    origin = get_origin(base)  # Returns Repository
    args = get_args(base)      # Returns (int,)
    
    if origin is Repository:
        print(f"UserRepository handles entities of type: {args[0]}")
# Output: UserRepository handles entities of type: <class 'int'>

Significance and Practical Use Cases

The __orig_bases__ attribute is critical in modern Python development for several reasons:

  1. Framework Metaprogramming and Dependency Injection: Libraries such as Pydantic, FastAPI, and SQLAlchemy rely on generic base classes to define repositories, schemas, and data mappers. __orig_bases__ allows these tools to automatically detect which data model a service or repository is configured to handle.
  2. Runtime Type Checking: Custom serializers and validation libraries use __orig_bases__ to enforce contracts at runtime without requiring duplicate class-level type declarations.
  3. Decoupled Architecture: Developers can create generic base implementations (like event handlers or CRUD operations) where subclasses supply domain models via generic parameters, keeping code declarative and type-safe.

The __orig_bases__ attribute bridges the gap between static typing and dynamic runtime introspection, ensuring generic parameterization is accessible across the entire lifecycle of an application.
