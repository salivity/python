Python UnboundLocalError: Outer Scope Assignment

In Python, an UnboundLocalError occurs when you attempt to read or modify a variable inside a function that shares a name with a variable in an outer scope, but you assign to it later in that same function. This article explains Python's compile-time scope resolution, why assigning to an outer-scope variable flags it as local, and how to resolve the issue using the global and nonlocal keywords or proper argument passing.

The Cause of the Error

When Python compiles a function, it inspects the entire function body to determine variable scopes. If a variable is assigned a value anywhere within the function (using =, +=, or other assignment operators), Python automatically designates that variable as local to the function for its entire execution.

Python makes this scoping decision before running any code. Consequently, if the function tries to read that variable before the line where the assignment occurs, Python searches the local namespace rather than the outer scope. Because the variable has not yet been assigned a value locally, Python raises UnboundLocalError: cannot access local variable 'x' where it is not associated with a value.

Example of the Problem

counter = 10

def increment():
    print(counter)  # Raises UnboundLocalError
    counter = counter + 1

increment()

Even though counter exists in the global scope and the read operation (print(counter)) appears before the assignment, Python marks counter as strictly local because of counter = .... When the interpreter reaches the print statement, counter does not yet have a local value bound to it.

The same error occurs when using augmented assignment operators like +=:

counter = 10

def increment():
    counter += 1  # Raises UnboundLocalError

increment()

Augmented assignment evaluates the right-hand read (counter + 1) before executing the assignment, failing because counter is considered an unbound local variable.

How to Fix UnboundLocalError

Depending on your architecture and where the variable resides, there are three main ways to resolve the issue.

1. Use the global Keyword

If the variable exists at the module level (global scope), declare it as global inside the function before accessing or modifying it.

counter = 10

def increment():
    global counter
    counter += 1
    print(counter)

increment()  # Outputs: 11

2. Use the nonlocal Keyword

If the variable exists in an enclosing (parent) function rather than the global module scope, use nonlocal to bind the inner function's reference to the outer function's variable.

def outer():
    count = 0
    
    def inner():
        nonlocal count
        count += 1
        return count
        
    return inner()

print(outer())  # Outputs: 1

3. Pass Variables as Parameters and Return Values

The cleanest approach avoids mutating outer variables altogether. Accept the value as an argument and return the updated value.

counter = 10

def increment(val):
    return val + 1

counter = increment(counter)
print(counter)  # Outputs: 11

This pattern eliminates unintended side effects and prevents scope-related errors naturally.
