Python -O Optimization Flag Explained

When you run a Python script with the -O optimization flag, the interpreter applies basic bytecode optimizations before execution. Specifically, it ignores all assert statements, sets the global built-in __debug__ constant to False, removes conditional blocks guarded by __debug__, and writes optimized bytecode to .opt-1.pyc cache files. While it provides modest execution speedups and reduced memory overhead, it does not perform deep compiler-level optimizations like C or C++ compilers do.

Removal of assert Statements

The most significant operational change introduced by the -O flag is the complete removal of assert statements. During the compilation to bytecode, Python bypasses assertions entirely rather than evaluating their conditions.

In standard execution:

assert user.is_authenticated, "Unauthorized access"

If user.is_authenticated is False, Python raises an AssertionError.

With python -O script.py: The interpreter removes this instruction from the generated bytecode. As a result, the assertion never runs, and no exception can be raised. Because of this behavior, you should never use assert statements for business logic, input validation, or security checks.

The __debug__ Constant Set to False

Python includes a read-only built-in boolean flag named __debug__, which normally defaults to True. When the -O flag is enabled, Python sets __debug__ to False.

Because __debug__ is evaluated at compile time, any code blocks wrapped inside an if __debug__: condition are stripped out of the bytecode entirely:

if __debug__:
    print("Debug profiling information:", heavy_diagnostic_call())

In standard mode, the diagnostic function runs. Under -O, Python treats the entire block as dead code and eliminates it, saving CPU cycles and memory.

Optimized Bytecode Caching (.opt-1.pyc)

When Python imports modules, it compiles them into bytecode and caches them in the __pycache__ directory.

  • Standard execution saves files with the format module.cpython-<version>.pyc.
  • Optimized execution (-O) saves files with the format module.cpython-<version>.opt-1.pyc.

This separation ensures that optimized bytecode does not overwrite standard bytecode, preventing conflicts when running scripts across different environments.

The -OO Flag Variation

Python also supports a secondary optimization level using -OO. This flag applies everything done by -O, but it also discards docstrings (__doc__ attributes) from functions, classes, and modules. This reduces memory usage further, though it can break libraries or frameworks that rely on docstrings for runtime introspection (such as certain test runners, documentation generators, or CLI parsers).

Performance Impact and Limitations

The -O flag does not transform Python into a high-performance compiled language. It does not unroll loops, inline functions, vectorize calculations, or optimize memory layout.

The performance gains come solely from:

  1. Skipping assertion checks.
  2. Removing code inside if __debug__: blocks.
  3. Loading slightly smaller bytecode files into memory.

For computationally heavy programs, relying on efficient data structures, built-in functions, or extensions like NumPy and PyPy will yield far greater performance improvements than the -O flag alone.
