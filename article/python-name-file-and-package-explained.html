Python name, file, and package Explained

When Python executes a script, its runtime environment automatically assigns specific values to built-in attributes, primarily __file__, __name__, and __package__. These variables dictate how the code identifies its location on the filesystem, determines whether it is running as a standalone entry point or an imported library, and resolves relative imports within an existing namespace.

The Role of __name__

The __name__ attribute identifies the module's execution context:

  • Direct Execution: When a script is executed directly from the terminal (e.g., python script.py), Python assigns __name__ = "__main__". This triggers code guarded by the if __name__ == "__main__": idiom.
  • Imported Execution: When imported into another script via import my_module, __name__ is set to the module's actual name (e.g., "my_module"), or its fully qualified dotted path (e.g., "package.submodule").
  • Module Execution Flag: When run with the -m switch (e.g., python -m package.script), __name__ is still set to "__main__", making it the top-level execution scope while retaining its package context.

The Role of __file__

The __file__ attribute contains the path of the script currently being loaded by the interpreter:

  • File-Based Execution: If Python loads the module from a file on disk, __file__ contains the path to that file. Since Python 3.9, direct execution resolves __file__ to an absolute path if invoked with an absolute path, or keeps it consistent with how the path was passed.
  • Dynamic Execution: If code is evaluated dynamically via eval(), exec(), or within an interactive REPL session, __file__ is not defined by default, raising a NameError if accessed directly unless manually injected.
  • Built-in and C-Extensions: Modules built directly into the Python interpreter or compiled C extensions may lack a __file__ attribute pointing to source files.

The Role of __package__

The __package__ attribute manages the parent package namespace, which Python uses to calculate explicit relative imports (such as from . import sibling):

  • Direct Script Execution: When executing python script.py, Python sets __package__ to None (or an empty string in older versions). Because no package namespace is defined, any relative import statement in that file will fail with an ImportError.
  • Package Execution via -m: Running python -m mypkg.script initializes __package__ to the parent package name ("mypkg"). This allows relative imports inside script.py to resolve correctly.
  • Imported Modules: When a module is imported normally within a package hierarchy, __package__ is set to the name of its immediate parent package. For top-level modules outside of any directory containing an __init__.py, __package__ is set to an empty string "".

Processing Sequence During Initialization

  1. Loader Initialization: Python's import machinery (importlib) identifies whether the target is a script, module, or package.
  2. Namespace Creation: A module object is created along with an internal dictionary (__dict__).
  3. Attribute Population: Python populates __file__ with the file system location, __name__ with either the module path or "__main__", and __package__ based on the module's position within the package tree.
  4. Code Execution: The interpreter runs the module's compiled bytecode sequentially within this initialized namespace.
