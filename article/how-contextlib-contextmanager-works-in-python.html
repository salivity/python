How contextlib.contextmanager Works in Python

Python's contextlib.contextmanager decorator transforms a standard generator function into a fully compliant context manager by wrapping it inside an internal helper class named _GeneratorContextManager. Instead of manually implementing the context management protocol with __enter__ and __exit__ methods, developers can write a generator that yields exactly once. The decorator manages the generator's execution lifecycle, driving it forward on entering the context block and resuming it—while routing any raised exceptions—when exiting the block.

The Context Management Protocol

A Python context manager must implement two methods:

  • __enter__(): Prepares the runtime context and optionally returns an object bound to the target specified in the as clause.
  • __exit__(): Cleans up the runtime context and handles any exceptions raised inside the with block.

When decorated with @contextmanager, calling the generator function does not run the code immediately. Instead, it returns an instance of _GeneratorContextManager initialized with the generator object.

The Role of __enter__

When a with statement begins, Python invokes the __enter__ method of the _GeneratorContextManager instance.

Internally, __enter__ calls next() on the generator object. This starts the generator and runs the code up to the yield statement. The value yielded by the generator is captured by __enter__ and returned as the result of the __enter__ call. If the with statement includes an as clause, this yielded value is bound to the target variable.

from contextlib import contextmanager

@contextmanager
def custom_resource():
    # 1. Executed during __enter__()
    resource = "Resource Initialized"
    
    yield resource  # Yielded value returned to the 'as' target
    
    # 2. Executed during __exit__()
    print("Resource Cleaned Up")

The Role of __exit__

The __exit__ method executes whenever the body of the with block finishes, whether it succeeds or encounters an unhandled exception.

1. Normal Execution

If no exceptions occur in the with block, __exit__ resumes the generator by calling next() (or passing None). This executes all cleanup code following the yield statement.

Because a context manager generator must yield only once, the generator is expected to terminate naturally. The resulting StopIteration exception is caught internally by _GeneratorContextManager and suppressed. If the generator yields a second value instead of finishing, a RuntimeError is raised.

2. Exception Handling

If an exception occurs within the with block, Python passes the exception details (type, value, traceback) into __exit__. Rather than calling next(), __exit__ injects the exception directly into the generator at the point of the yield statement using generator.throw():

gen.throw(exc_type, exc_value, exc_traceback)

This behavior allows the generator to handle the failure using a standard try...except...finally block.

  • If the generator catches the exception and exits normally without re-raising, __exit__ returns True, signaling to Python that the exception has been suppressed.
  • If the generator does not catch the exception, or if it raises a different exception during cleanup, the exception propagates up the call stack as normal.
