How Python dis.dis Evaluates Stack Bytecode

This article explores how Python's built-in dis module illustrates stack-based bytecode evaluation during simple arithmetic operations. By disassembling basic mathematical functions with dis.dis(), you will learn how CPython utilizes a Last-In, First-Out (LIFO) value stack to load values, execute arithmetic opcodes, and return results.

The CPython Stack Machine

CPython executes code using a stack-based virtual machine. Unlike register-based virtual machines, which store operands in explicitly addressed registers, a stack machine performs operations by pushing operands onto an evaluation stack and popping them off when executing instructions.

The dis module disassembles CPython bytecode into human-readable instructions, exposing the precise sequence of stack manipulations that occur under the hood.

Disassembling a Basic Addition Function

Consider a minimal arithmetic function:

import dis

def add(a, b):
    return a + b

dis.dis(add)

Running this code produces output similar to the following (Python 3.11+):

  2           0 RESUME                   0

  3           2 LOAD_FAST                0 (a)
              4 LOAD_FAST                1 (b)
              6 BINARY_OP                0 (+)
             10 RETURN_VALUE

(Note: In Python 3.10 and earlier, BINARY_OP 0 (+) is represented as BINARY_ADD.)

Reading the dis.dis() Output Columns

The disassembly output is organized into distinct columns:

  1. Line Number (2, 3): The source code line where the instruction originates.
  2. Byte Offset (0, 2, 4, ...): The index of the instruction in the compiled bytecode sequence.
  3. Opcode Name (LOAD_FAST, BINARY_OP, etc.): The human-readable name of the bytecode instruction.
  4. Opcode Argument (0, 1): The internal index or configuration parameter used by the virtual machine.
  5. Resolved Argument ((a), (b), (+)): A friendly interpretation of the argument provided by dis.dis().

Step-by-Step Stack Evaluation

To understand how CPython evaluates return a + b, trace the evaluation stack through each instruction:

1. LOAD_FAST 0 (a)

Python looks up local variable a from the current execution frame and pushes its reference onto the top of the stack (TOS).

  • Stack State: [a]

2. LOAD_FAST 1 (b)

Python fetches local variable b and pushes it onto the stack.

  • Stack State: [a, b] (where b is TOS, and a is TOS1)

3. BINARY_OP 0 (+)

The virtual machine executes the addition operation. It pops the top two values from the stack:

  • TOS (b) is popped as the right-hand operand.
  • TOS1 (a) is popped as the left-hand operand.

It executes a + b (invoking the __add__ method) and pushes the resulting sum back onto the top of the stack.

  • Stack State: [result]

4. RETURN_VALUE

The virtual machine pops the current TOS (result) and terminates the frame, passing the value back to the caller.

  • Stack State: [] (Empty)

Handling Precedence and Compound Arithmetic

The stack architecture naturally accommodates operator precedence without requiring parentheses in bytecode. Consider an expression with multiple operations:

def calculate(x, y):
    return (x + y) * 2

dis.dis(calculate)

The output highlights how intermediate results remain on the stack:

  2           0 RESUME                   0

  3           2 LOAD_FAST                0 (x)
              4 LOAD_FAST                1 (y)
              6 BINARY_OP                0 (+)
             10 LOAD_CONST               1 (2)
             12 BINARY_OP                5 (*)
             16 RETURN_VALUE

The evaluation proceeds sequentially:

  1. x and y are pushed: [x, y]
  2. BINARY_OP (+) evaluates x + y and pushes the sum: [sum]
  3. LOAD_CONST (2) pushes the literal integer 2: [sum, 2]
  4. BINARY_OP (*) pops 2 and sum, multiplies them, and pushes the product: [product]
  5. RETURN_VALUE returns the product.

Through dis.dis(), CPython demonstrates that all arithmetic expressions—regardless of complexity—are evaluated by breaking formulas down into linear, stack-oriented operations.
