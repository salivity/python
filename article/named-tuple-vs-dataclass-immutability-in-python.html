NamedTuple vs Dataclass Immutability in Python

In Python, the primary difference regarding immutability between typing.NamedTuple and a standard @dataclass lies in their underlying architecture and default behavior. A NamedTuple is an immutable, tuple-based data structure by default, meaning its fields cannot be modified after instantiation. Conversely, a standard @dataclass is completely mutable upon creation and requires an explicit frozen=True flag to enforce read-only behavior through generated accessor guards.

Default Mutability

By default, standard dataclasses allow in-place attribute reassignment:

from dataclasses import dataclass
from typing import NamedTuple


@dataclass
class PointDataclass:
    x: int
    y: int


point_dc = PointDataclass(1, 2)
point_dc.x = 10  # Allowed: point_dc.x is now 10

typing.NamedTuple creates a subclass of Python’s built-in tuple. Because tuples are immutable primitives at the C-extension level, fields cannot be rebound:

class PointNamedTuple(NamedTuple):
    x: int
    y: int


point_nt = PointNamedTuple(1, 2)
point_nt.x = 10  # Raises AttributeError: can't set attribute

Emulated Immutability vs. Structural Immutability

To make a dataclass immutable, you must explicitly mark it as frozen: @dataclass(frozen=True). However, the mechanism used by a frozen dataclass differs fundamentally from NamedTuple:

  • NamedTuple (Structural): Immutability is baked into the type itself because it inherits from tuple. The instance lacks a dynamic __dict__ and prevents attribute reassignment at the C-API level.
  • Frozen Dataclass (Emulated): The @dataclass(frozen=True) decorator dynamically generates custom __setattr__ and __delattr__ methods that raise a dataclasses.FrozenInstanceError whenever a mutation is attempted.

Because a frozen dataclass relies on method-level guards in Python, its immutability can be bypassed by directly invoking object.__setattr__(instance, 'attr', value). A NamedTuple cannot be bypassed in this manner.

The Shallow Immutability Limitation

Neither structure provides deep immutability. If a field references a mutable object—such as a list or a dict—the internal state of that object can still be altered in both NamedTuple and frozen dataclasses:

class ContainerNT(NamedTuple):
    items: list


nt = ContainerNT(items=[1, 2])
nt.items.append(3)  # Allowed: the list is modified in place

Performance and Memory Implications

Because typing.NamedTuple is backed by a tuple, it has a smaller memory footprint and faster instantiation times compared to a standard dataclass. A frozen dataclass can approach this memory efficiency only if configured with @dataclass(frozen=True, slots=True) in Python 3.10 and later.
