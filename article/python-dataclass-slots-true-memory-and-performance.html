Python Dataclass slots=True Memory and Performance

Python 3.10 introduced the slots=True parameter to the @dataclass decorator, providing a streamlined way to automatically generate classes that use __slots__. This article explores how enabling slots=True eliminates the default dynamic per-instance dictionary, drastically lowering memory overhead and accelerating attribute access times for data-heavy applications.

How Default Dataclasses Handle Attributes

By default, Python objects—including standard dataclasses—store their instance attributes in a dynamic dictionary named __dict__. This dictionary grants the flexibility to add, modify, or delete attributes on an instance at runtime.

However, a Python dictionary relies on a hash table implementation. Even an empty dictionary consumes a noticeable amount of memory, and as attributes are added, the hash table pre-allocates space to minimize resizing operations. When you instantiate thousands or millions of dataclass objects, the collective memory overhead of these per-instance dictionaries becomes a major performance bottleneck.

Memory Reduction with slots=True

When you define a dataclass with @dataclass(slots=True), Python bypasses the creation of the __dict__ and __weakref__ attributes for each instance (unless explicitly requested or inherited).

from dataclasses import dataclass

@dataclass(slots=True)
class Coordinate:
    x: float
    y: float
    z: float

Instead of an individual hash map for each instance, Python creates a fixed-size array of pointers directly inside the C structure of the object. The class object manages attribute lookups using descriptors at specific memory offsets.

This change leads to substantial memory savings:

  • Overhead Reduction: A conventional dataclass instance with a few attributes often consumes around 150 to 200 bytes. With slots=True, that same instance typically drops to 48 to 64 bytes.
  • Scalability: When dealing with millions of records—such as streaming data, large datasets in memory, or simulation entities—enabling slots=True can reduce overall heap usage by 50% to 70%.

Execution Performance and Attribute Access

In addition to smaller memory footprints, slots=True speeds up attribute reads and writes:

  1. Direct Memory Offsets: Accessing an attribute on a standard object requires a hash calculation and a lookup within __dict__. Slotted attributes use descriptors that map directly to fixed offsets in the object's memory structure, implemented directly in C.
  2. Improved Cache Locality: Because slotted objects are significantly smaller, more instances fit into CPU L1/L2 caches simultaneously. This reduces CPU cache misses during iterations over large collections of objects, leading to faster execution times in tight loops.

Benchmark tests typically show that reading and writing attributes on slotted dataclasses is 15% to 25% faster compared to standard dataclasses.

Trade-offs and Considerations

While slots=True provides clear performance benefits, it introduces a few behavioral changes:

  • No Dynamic Attributes: You cannot assign new attributes to an instance that were not declared in the class definition. Attempting to assign an undeclared attribute raises an AttributeError.
  • Inheritance Constraints: Inheriting from multiple slotted classes can lead to TypeError exceptions if more than one parent class defines non-empty slots.
  • Weak References: Instances cannot be weakly referenced by default unless __weakref__ is explicitly included in the slot definitions.

For most data transfer objects and high-volume data structures in Python 3.10 and newer, @dataclass(slots=True) is an effective, zero-boilerplate optimization for reducing memory consumption and improving runtime throughput.
