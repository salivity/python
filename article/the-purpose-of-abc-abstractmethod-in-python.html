The Purpose of @abc.abstractmethod in Python

Decorating a method with @abc.abstractmethod in a Python abstract base class establishes a formal contract that forces subclasses to provide an implementation for that method. This article explains how the decorator works, why it is used to define consistent interfaces, and how Python enforces it at runtime to prevent the instantiation of incomplete classes.

Enforcing Interface Implementation

The primary purpose of @abc.abstractmethod is to ensure that derived classes implement specific behavior. When a class inherits from abc.ABC (or uses abc.ABCMeta as its metaclass) and contains at least one method decorated with @abc.abstractmethod, Python marks that class as abstract.

If a subclass inherits from this abstract base class and fails to override all abstract methods, Python will raise a TypeError when you attempt to instantiate the subclass. This shifts error detection from runtime execution to the moment of object creation, preventing bugs caused by missing method definitions.

from abc import ABC, abstractmethod

class Database(ABC):
    @abstractmethod
    def connect(self):
        """Must be implemented by subclasses."""
        pass

class PostgresDatabase(Database):
    # Missing connect() implementation
    pass

# Raises TypeError: Can't instantiate abstract class PostgresDatabase with abstract method connect
db = PostgresDatabase()

Preventing Direct Instantiation

An abstract base class is designed to serve as a blueprint, not a functioning object. Adding @abc.abstractmethod prevents developers from directly instantiating the base class itself. Attempting to run Database() in the example above will also trigger a TypeError. This ensures that incomplete or purely conceptual classes are never executed in production.

Facilitating Polymorphism and Code Reliability

By using @abc.abstractmethod, you define a reliable Application Programming Interface (API) for your codebase. Other components in the system can depend on the base class specification with the guarantee that any concrete subclass will have the required methods available with the expected signatures. This facilitates clean polymorphism, as functions can accept the base type and safely call abstract methods without having to verify whether the underlying object implemented them.

Providing Default Shared Logic

An abstract method in Python is not required to be empty. You can write a default implementation inside a method decorated with @abc.abstractmethod. While subclasses are still strictly required to override the method to allow instantiation, they can use super().method_name() to reuse the common logic provided by the base class.
