Python tracemalloc get_traced_memory Guide

Python's built-in tracemalloc module provides a lightweight way to track memory allocations made by the Python interpreter. This article explains how the tracemalloc.get_traced_memory() function operates, how it hooks into Python's internal memory allocators to capture allocation metrics, and how it determines both the current and peak memory usage of a running program.

The Return Value: Current and Peak Usage

When you invoke tracemalloc.get_traced_memory(), it returns a tuple of two integers:

current, peak = tracemalloc.get_traced_memory()

Both values are reported in bytes:

  • current: The total size of memory currently allocated by Python processes that has not yet been released.
  • peak: The highest memory allocation reached (the high-water mark) since tracemalloc.start() was called or since the last call to tracemalloc.reset_peak().

How tracemalloc Hooks Into Memory

Python handles memory through internal allocators such as pymalloc (optimized for small objects) and raw wrappers around the system's standard malloc and free implementations.

When you run tracemalloc.start(), Python installs hooks into these internal memory management APIs (PyMem_RawMalloc, PyMem_Malloc, and related realloc/free functions). Every time an object is created or destroyed, the hook executes before the underlying memory allocation or deallocation occurs.

Tracking Current Allocation

The current metric is maintained using an internal atomic counter.

  1. Whenever an allocation request succeeds, tracemalloc adds the allocated byte size to this global counter.
  2. Whenever a block of memory is freed, the counter is decremented by the exact size of that released block.

Because of this, current provides an exact snapshot of the net bytes active under Python’s memory manager at the microsecond get_traced_memory() is evaluated.

Determining the Peak Allocation

The peak metric records the maximum value that the current allocation counter has ever reached during tracing.

Each time a new allocation increases the current counter, the allocator compares the new value to the stored peak value:

if current > peak:
    peak = current

If the newly calculated current exceeds peak, the high-water mark is updated immediately. Deallocations reduce current but have no effect on peak, preserving the historic maximum.

Controlling the Scope with reset_peak()

By default, peak tracks the lifetime of the tracing session. However, you can isolate specific blocks of code using tracemalloc.reset_peak(). Calling this sets the peak value equal to the current value at that exact moment. Any subsequent memory spikes will measure relative to that baseline, allowing you to benchmark discrete functions or loops without prior allocations skewing the peak statistic.

Scope Limitations

tracemalloc.get_traced_memory() exclusively monitors allocations routed through Python's official memory management APIs. Memory allocated by external C libraries or native extensions using raw, unhooked system calls (such as a direct C malloc() that bypasses Python APIs) will not be reflected in either the current or peak metrics.
