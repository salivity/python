What Objects Does gc.get_objects() Return?

Python's gc.get_objects() function returns a Python list containing all objects currently tracked by the CPython cyclical garbage collector, excluding the returned list itself. While commonly used for heap introspection and memory leak detection, it does not provide a complete representation of every object allocated in memory. Instead, it exclusively returns container objects and custom types capable of participating in reference cycles, omitting most atomic immutable types.

Tracked Objects

CPython’s garbage collector is designed to detect and resolve circular references. Because reference counting handles straightforward deallocations, the garbage collector only monitors objects that can hold references to other objects.

When you invoke gc.get_objects(), the returned list contains:

  • Custom Class Instances: Instances of user-defined classes and their underlying __dict__ attributes.
  • Mutable Containers: Standard collections such as list, dict, and set.
  • Functions, Modules, and Classes: Function objects, generator objects, module objects, and class definitions (types).
  • Execution Frames: Tracebacks and frame objects currently active or retained in closures.
  • Complex Tuples: Tuples that contain references to at least one mutable or tracked object.

Untracked Objects

gc.get_objects() does not inspect raw heap memory; it only traverses the doubly linked lists maintained by the GC generations. Consequently, several categories of objects are missing from its output:

  • Atomic Primitives: Non-container types such as integers (int), floating-point numbers (float), booleans (bool), and strings (str) are never tracked because they cannot reference other objects.
  • Stateless or Immutable Singletons: Objects like None, Ellipsis, and empty tuples are not tracked.
  • Optimized Tuples: A tuple consisting entirely of atomic immutables (such as (1, "text", 3.14)) is untracked by the garbage collector to reduce overhead.
  • Untracked Dictionaries: CPython implements an optimization that untracks dictionaries under certain conditions. Dictionaries containing only string keys and primitive values (such as module namespaces or specific instance dictionaries) may be untracked until a complex object is inserted.

The generation Parameter

Starting in Python 3.8, gc.get_objects() accepts an optional generation argument:

  • gc.get_objects(generation=0): Returns only the youngest objects (Generation 0).
  • gc.get_objects(generation=1): Returns objects that have survived one collection cycle (Generation 1).
  • gc.get_objects(generation=2): Returns the oldest, long-lived objects (Generation 2).
  • gc.get_objects(): Returns all tracked objects across all three generations.

Heap Introspection Considerations

Because gc.get_objects() excludes atomic primitives, iterating over its output will not reveal memory occupied by large strings, byte buffers, or millions of cached integers directly. To find untracked objects during heap debugging, you must inspect the contents and attributes of the tracked container objects returned by the function using tools like sys.getsizeof() or traversal libraries like objgraph.
