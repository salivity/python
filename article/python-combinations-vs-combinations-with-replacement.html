Python Combinations vs Combinations with Replacement

Python's itertools module offers efficient tools for handling combinatorics, with the primary distinction between itertools.combinations() and itertools.combinations_with_replacement() lying in whether individual elements can be repeated within a generated subset. While standard combinations select elements without replacement—ensuring no single element appears more than once per output tuple—combinations_with_replacement() allows individual items to be chosen multiple times. This article breaks down the technical differences, mathematical principles, behavior when subset size exceeds input length, and practical code examples for both functions.

The Core Difference: Item Reuse

Both functions return \(r\)-length subsequences of elements from the input iterable, preserving the relative order of the items without treating different orderings as distinct (unlike permutations). The distinction is purely about item reuse:

  • combinations(iterable, r): Produces combinations without replacement. Each item from the input can only be used once per combination based on its index position.
  • combinations_with_replacement(iterable, r): Produces combinations with replacement. Any item can be repeated up to \(r\) times in a single combination.

Code Comparison

import itertools

data = ['A', 'B', 'C']

# Standard combinations (r=2)
standard = list(itertools.combinations(data, 2))
print("Standard:", standard)
# Output: [('A', 'B'), ('A', 'C'), ('B', 'C')]

# Combinations with replacement (r=2)
with_replacement = list(itertools.combinations_with_replacement(data, 2))
print("With Replacement:", with_replacement)
# Output: [('A', 'A'), ('A', 'B'), ('A', 'C'), ('B', 'B'), ('B', 'C'), ('C', 'C')]

Notice that combinations_with_replacement() includes self-paired tuples like ('A', 'A'), ('B', 'B'), and ('C', 'C'), which are omitted by standard combinations.

Mathematical Differences

The number of generated results differs significantly between the two methods:

  • Standard Combinations: The total number of outcomes is calculated using the standard binomial coefficient: \[\binom{n}{r} = \frac{n!}{r!(n - r)!}\] For \(n = 3\) and \(r = 2\), the count is \(\frac{3!}{2!1!} = 3\).

  • Combinations with Replacement: The total number of outcomes is calculated as: \[\binom{n + r - 1}{r} = \frac{(n + r - 1)!}{r!(n - 1)!}\] For \(n = 3\) and \(r = 2\), the count is \(\frac{4!}{2!2!} = 6\).

Handling \(r\) Larger Than Input Length

A critical operational difference occurs when the requested combination length \(r\) is greater than the number of items \(n\) in the input iterable:

  • combinations(): If \(r > n\), it returns an empty iterator because it is impossible to choose more unique items than exist in the pool.
  • combinations_with_replacement(): If \(r > n\), it continues to work normally because existing elements can be repeated indefinitely to satisfy the requested length.
items = [1, 2]

# r is greater than len(items)
print(list(itertools.combinations(items, 3)))
# Output: []

print(list(itertools.combinations_with_replacement(items, 3)))
# Output: [(1, 1, 1), (1, 1, 2), (1, 2, 2), (2, 2, 2)]

Summary of Use Cases

  • Use itertools.combinations() when modeling scenarios where an item cannot be picked again once chosen, such as dealing a hand of cards from a deck or picking committee members from a group.
  • Use itertools.combinations_with_replacement() when modeling independent trials where outcomes can repeat, such as rolling multiple identical dice, flipping coins, or making change with a set of coin denominations.
