Python IntFlag vs Flag Type Compatibility

Python's enum module provides both Flag and IntFlag to support bitwise operations and bitmasks, but they handle type compatibility fundamentally differently. While both classes allow members to be combined using bitwise operators like |, &, and ^, Flag strictly isolates members within their defined enumeration type, whereas IntFlag subclasses int to maintain bidirectional compatibility with raw Python integers.

Inheritance and Type Hierarchies

The primary architectural distinction lies in class inheritance. A member of an enum.Flag is an instance of Flag and Enum, but it does not inherit from int.

Conversely, enum.IntFlag uses multiple inheritance: its members inherit from both int and Flag. Because an IntFlag member is formally an instance of int, isinstance(MyIntFlag.A, int) evaluates to True. For standard Flag members, isinstance(MyFlag.A, int) evaluates to False.

Equality and Comparisons

Because of their inheritance differences, equality checks behave differently when comparing members to standard numeric integers:

  • enum.Flag: Compares unequal to standard integers. Checking MyFlag.READ == 1 always returns False, and ordered comparisons such as MyFlag.READ > 0 raise a TypeError.
  • enum.IntFlag: Compares directly with standard integers based on numeric value. Evaluating MyIntFlag.READ == 1 returns True. It also supports relative comparisons like <, <=, >, and >= against standard integers.

Bitwise Operations with Integers

When combining members using bitwise operators (&, |, ^, ~), type constraints dictate what operands are permitted:

  • enum.Flag: Only permits bitwise operations between instances of the exact same Flag class. Attempting an operation like MyFlag.READ | 2 or combining two different Flag types raises a TypeError.
  • enum.IntFlag: Permits bitwise operations with standard integers as well as other IntFlag classes. An expression like MyIntFlag.READ | 2 executes successfully. If an operation results in a value matching an existing member, it returns that member; otherwise, it returns a valid composite IntFlag or standard integer.

Choosing Between Flag and IntFlag

enum.Flag is the preferred choice for internal application logic where type safety is prioritized. It prevents subtle bugs caused by accidentally mixing raw numbers, file descriptors, or unrelated flags with the enumeration.

enum.IntFlag is intended for interoperability. It is best suited for interfacing with C libraries, operating system system-calls (such as os.open flags), network protocols, or legacy APIs that expect primitive integer values instead of custom object instances.
