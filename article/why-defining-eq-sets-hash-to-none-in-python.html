Why Defining eq Sets hash to None in Python

When you define a custom __eq__ method in a Python class without defining __hash__, Python automatically sets __hash__ = None, rendering the class unhashable. This article explains the technical rationale behind this behavior, focusing on the fundamental invariant of hash-based collections, the risk of data corruption, and how to properly restore hashing capabilities when appropriate.

The Hash Invariant

Python's hash-based collections, such as dict and set, rely on a strict mathematical contract:

If two objects are equal according to __eq__, their hash values must also be equal (a == b implies hash(a) == hash(b)).

The converse does not need to be true; two different objects can share the same hash value (a hash collision). However, equal objects must never produce different hashes. If equal objects produce different hashes, hash tables will store them in different buckets. Consequently, a lookup for a key that equals an existing key will look in the wrong bucket and fail to find it, causing silent retrieval bugs and duplicate entries in sets.

The Problem with Default Inheritance

By default, any user-defined class inherits both __eq__ and __hash__ from object:

  • object.__eq__ compares object identity (self is other).
  • object.__hash__ derives a hash code from the object's identity (typically its memory address).

Under the default implementation, two distinct instances are never equal, so their differing hashes never violate the hash invariant.

However, when you implement a custom __eq__, you almost always base equality on an object's internal state rather than its identity:

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        return isinstance(other, Point) and (self.x, self.y) == (other.x, other.y)

If Python allowed this class to inherit object.__hash__, two distinct instances with identical coordinates would be equal (Point(1, 2) == Point(1, 2)), but their hash codes would differ because their memory addresses differ. This directly violates the hash contract.

Why Python Enforces __hash__ = None

Rather than allowing classes to silently inherit an invalid __hash__ implementation, Python automatically sets __hash__ = None on any class that defines __eq__ without __hash__.

Setting __hash__ = None informs Python's runtime that instances of this class are intentionally unhashable. When an operation attempts to calculate the hash—such as adding an instance to a set or using it as a dict key—Python immediately raises a clear error:

p = Point(1, 2)
hash(p)  # Raises TypeError: unhashable type: 'Point'

This enforces the design principle that failing early and loudly is preferable to silently corrupting data structures.

Mutability and Hashing

Another reason behind this design is that classes defining custom equality are frequently mutable.

If a mutable object's hash is computed from its attributes, modifying those attributes changes the hash value. If that object is already stored inside a set or dictionary, the container will look for it in a bucket corresponding to its new hash rather than the bucket where it was originally inserted, effectively "losing" the object.

Because Python cannot automatically determine whether your class is immutable, it assumes that defining a custom equality check makes the object unsuitable for hashing by default.

How to Restore Hashing

Depending on your use case, there are two primary ways to restore hashing:

1. Implement a Custom Hash (For Immutable Objects)

If your object's state does not change after instantiation, implement __hash__ using the same attributes compared in __eq__:

class Point:
    def __init__(self, x, y):
        self._x = x
        self._y = y

    def __eq__(self, other):
        return isinstance(other, Point) and (self._x, self._y) == (other._x, other._y)

    def __hash__(self):
        return hash((self._x, self._y))

2. Restore Identity Hashing

If you want instances to compare equality based on value in logic expressions, but still be distinguished by identity inside collections, you can explicitly restore identity hashing:

class Point:
    __hash__ = object.__hash__

    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        return isinstance(other, Point) and (self.x, self.y) == (other.x, other.y)

Note: Doing this reintroduces the risk of a == b producing different hashes, so it should be used with extreme caution.
