How to Read Package Assets with importlib.resources

The importlib.resources module provides a modern, secure, and standardized interface for accessing non-code assets—such as configuration files, templates, schemas, and media—packaged directly within Python modules. Introduced in Python 3.7 and modernized with a path-like API in Python 3.9, it replaces older, brittle techniques like manual __file__ path manipulation and the deprecated pkg_resources API, ensuring assets are accessible whether a package is installed in an editable directory, packaged as a wheel, or loaded from a zip archive.

The Modern files() API and Traversable

The primary entry point in modern Python is importlib.resources.files(). Passing an installed module's name or module object returns a Traversable instance. This object mirrors a subset of Python's standard pathlib.Path interface, allowing developers to navigate an asset tree using familiar methods.

import importlib.resources

# Returns a Traversable pointing to the package root
pkg_root = importlib.resources.files("my_package")

# Navigate into nested asset directories
config_path = pkg_root / "assets" / "config.json"
# Or using joinpath:
config_path = pkg_root.joinpath("assets", "config.json")

Direct Asset Reading

importlib.resources offers direct reading methods without the need to manage file handles manually. These operations automatically handle opening, reading, and closing the resource stream:

  • Text Content: .read_text(encoding="utf-8") reads the resource directly into a string.
  • Binary Content: .read_bytes() loads raw binary data directly into memory.
data_file = importlib.resources.files("my_package.data") / "lookup.csv"

# Read as text
csv_content = data_file.read_text(encoding="utf-8")

# Read as bytes
binary_data = data_file.read_bytes()

Stream-Based Access

For large files where loading the entire asset into memory is inefficient, Traversable instances support standard stream-based access via the .open() method. This works seamlessly with context managers:

resource = importlib.resources.files("my_package") / "large_dataset.bin"

with resource.open("rb") as stream:
    chunk = stream.read(4096)
    while chunk:
        process(chunk)
        chunk = stream.read(4096)

Extracting Physical File Paths via as_file

Certain external libraries (such as C extensions, SQLite, or GUI toolkits) require a physical path on the operating system's filesystem, rather than an abstract stream. If a package is distributed as a zip file, standard paths do not natively exist.

The importlib.resources.as_file() context manager solves this by temporarily extracting the resource to the local filesystem if necessary, yielding a real pathlib.Path, and cleaning it up once the context block exits.

resource = importlib.resources.files("my_package") / "database.sqlite"

with importlib.resources.as_file(resource) as actual_path:
    # actual_path is guaranteed to be a real pathlib.Path
    connection = sqlite3.connect(actual_path)
    # The temporary file is cleaned up upon exiting the block if it was extracted

Directory Inspection and Discovery

importlib.resources enables runtime discovery of static assets without knowing the exact file names ahead of time. The Traversable object supports directory queries:

  • .iterdir() yields Traversable objects for all contents inside a package directory.
  • .is_file() and .is_dir() allow inspection of asset types.
templates_dir = importlib.resources.files("my_package") / "templates"

available_templates = [
    item.name for item in templates_dir.iterdir() if item.is_file() and item.name.endswith(".html")
]

Compatibility Across Package Formats

A key capability of importlib.resources is transport abstraction. Assets are accessed using loaders defined by Python’s import system (PEP 302). Whether a package resides in a standard directory on disk, within an unextracted .whl or .egg, or inside a frozen executable (such as PyInstaller), code utilizing importlib.resources runs identically without environment-specific modifications.
