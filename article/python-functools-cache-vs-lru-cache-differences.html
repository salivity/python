Python functools cache vs lru_cache Differences

Python 3.9 introduced functools.cache as a modern, lightweight alternative to the long-standing functools.lru_cache decorator. While both tools provide memoization to store and reuse the return values of expensive function calls, they differ fundamentally in memory management, execution overhead, and API simplicity. This guide outlines the key technical differences between the two decorators and explains when to use each.

1. Cache Size and Eviction Policy

The most significant distinction between the two decorators is how they manage cache size and data eviction:

  • functools.lru_cache: Implements a Least Recently Used (LRU) eviction strategy. By default, it stores up to 128 entries (maxsize=128). When the cache reaches capacity, it automatically discards the least recently accessed items to make room for new results. You can customize this threshold by setting maxsize to any integer.
  • functools.cache: Has an unbounded cache size. It never evicts old entries, functioning identically to functools.lru_cache(maxsize=None). The cache grows indefinitely for every unique set of arguments passed to the decorated function.

2. Performance and Overhead

Because functools.cache does not enforce a maximum size, it eliminates the need to track access order:

  • Lower Overhead: functools.cache uses a simpler underlying C implementation that skips the logic required to maintain an LRU doubly linked list. As a result, it is slightly faster than lru_cache in terms of execution time.
  • Locking and Mutexes: While both implementations are thread-safe, functools.cache incurs less lock contention because it only inserts items into a dictionary without constantly updating access markers.

3. Memory Safety

  • functools.lru_cache: Safe for long-running processes (such as web services or workers) where functions receive a wide or unpredictable variety of arguments. The bounded size ensures memory usage remains predictable and capped.
  • functools.cache: Poses a risk of memory leaks if used with functions that take varied or infinite argument combinations (e.g., timestamps, unique IDs, or raw user queries). Because entries are never cleared automatically, memory consumption will steadily increase until the process terminates.

4. Syntax and Arguments

  • functools.cache: Designed without configuration parameters. It is applied cleanly as a bare decorator: 
    from functools import cache

@cache
def factorial(n):
    return n * factorial(n - 1) if n else 1
  • functools.lru_cache: Accepts configuration parameters, including maxsize and typed. Setting typed=True caches distinct results for arguments of different types (e.g., treating 3 and 3.0 as separate keys): 
    from functools import lru_cache

@lru_cache(maxsize=256, typed=True)
def compute_data(value):
    return value * 2

When to Use Each

  • Use functools.cache for recursive algorithms (like dynamic programming, tree traversals, or combinatorics) and functions with a strictly finite, small set of possible inputs where maximum speed is desired.
  • Use functools.lru_cache for networked applications, database queries, web endpoints, or any scenario where inputs are diverse, unpredictable, or running indefinitely in production.
