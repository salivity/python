How Python Combines Yield With Async Iteration

Python asynchronous generators blend the lazy evaluation of traditional generators with the non-blocking concurrency of asyncio. By placing the yield keyword inside an async def function, Python creates an object that pauses execution to deliver data to a consumer while also being able to suspend execution to wait for external I/O events. This article explores how Python ties these two paradigms together through the asynchronous iteration protocol, the interaction between yield and await, and how data flows through an async for loop.

The Mechanics of the Async Generator Function

A standard generator function uses def and yield to implement the iterator protocol (__iter__ and __next__). An asynchronous generator function is defined using async def and contains at least one yield statement.

When you call an asynchronous generator function, it does not immediately execute the function body. Instead, it returns an asynchronous generator object. This object adheres to the asynchronous iterator protocol by implementing two core special methods:

  • __aiter__(): Returns the asynchronous generator object itself.
  • __anext__(): Returns an awaitable object that, when awaited, resolves to the next yielded value or raises a StopAsyncIteration exception to signal completion.

Interleaving await and yield

The primary utility of an asynchronous generator is the ability to interleave operations that await coroutines with operations that produce values.

import asyncio

async def fetch_pages(urls):
    for url in urls:
        # Suspend execution to perform I/O
        data = await fake_http_get(url)
        # Yield the processed result to the consumer
        yield data

In this flow, two distinct pausing mechanisms work in concert:

  1. Pausing on await: When execution hits an await expression, the generator suspends itself and yields control back to the event loop, allowing other asynchronous tasks to run while waiting for an external event (like a socket read or a database query).
  2. Pausing on yield: When execution reaches a yield statement, the generator resolves the awaitable returned by __anext__(), providing the yielded value to the consumer. The generator's state is preserved exactly at that point until the consumer requests the subsequent item.

Consumption via async for

Asynchronous generators cannot be consumed by standard for loops or the built-in next() function because their steps are inherently asynchronous. Instead, they are consumed using the async for statement.

Under the hood, the async for construct translates to the following sequence:

  1. It retrieves the iterator by calling gen.__aiter__().
  2. At each iteration, it calls gen.__anext__(), which returns a coroutine.
  3. It awaits that coroutine to retrieve the value.
  4. If the coroutine resolves with a value, the loop body executes.
  5. If the coroutine raises StopAsyncIteration, the loop terminates gracefully.
async def main():
    async for page in fetch_pages(url_list):
        print(page)

Generator Lifecycle and Cleanup

Asynchronous iteration semantics also govern how cleanup is handled. Traditional generators use close() to terminate iteration early, raising a GeneratorExit inside the frame.

Because asynchronous generators may need to perform asynchronous cleanup—such as closing network connections or committing transactions—they provide an aclose() method. Calling await gen.aclose() returns an awaitable that resumes the generator, raises GeneratorExit at the point of suspension, executes any enclosing finally blocks (even those containing await expressions), and completes the generator's lifecycle cleanly within the event loop.
