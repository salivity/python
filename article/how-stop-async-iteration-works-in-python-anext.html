How StopAsyncIteration Works in Python anext

In Python, the asynchronous iteration protocol relies on the StopAsyncIteration exception to determine when a stream of asynchronous data has ended. Within a custom class implementing the __anext__ method, raising StopAsyncIteration serves as the explicit termination signal to consumer constructs such as async for loops. This article covers the role of StopAsyncIteration, how the asynchronous loop catches and processes it, and how to properly implement it in custom asynchronous iterators.

The Asynchronous Iteration Protocol

Python defines asynchronous iteration via two core dunder methods: __aiter__ and __anext__.

  1. __aiter__(self): Returns the asynchronous iterator object itself.
  2. __anext__(self): An awaitable method that returns the next value in the sequence on each call.

Because __anext__ is an asynchronous method, it cannot simply return an empty value or None to indicate completion, as None might be a valid yielded item. Instead, the language specification dictates that __anext__ must raise StopAsyncIteration once the sequence is exhausted.

How StopAsyncIteration Terminates the Loop

When an async for loop iterates over an asynchronous iterable, it implicitly awaits the __anext__ method on each pass. Behind the scenes, the loop operates similarly to a while True block wrapped in an exception handler:

iterator = iterable.__aiter__()
while True:
    try:
        item = await iterator.__anext__()
    except StopAsyncIteration:
        break
    # Loop body executes here

When StopAsyncIteration is raised:

  • Execution within __anext__ halts immediately.
  • The exception propagates out to the caller.
  • The async for construct catches StopAsyncIteration and executes a clean break, terminating iteration without bubbling the exception to the outer scope.

Implementation Example

Below is an implementation of a custom asynchronous iterator that streams numbers up to a specified limit:

import asyncio

class AsyncCounter:
    def __init__(self, limit):
        self.limit = limit
        self.current = 0

    def __aiter__(self):
        return self

    async def __anext__(self):
        # Simulate asynchronous I/O
        await asyncio.sleep(0.1)

        if self.current < self.limit:
            val = self.current
            self.current += 1
            return val
        else:
            # Signal that iteration has finished
            raise StopAsyncIteration

async def main():
    async for number in AsyncCounter(3):
        print(number)

asyncio.run(main())

In this example, once self.current reaches 3, the conditional branch raises StopAsyncIteration. The async for loop catches this exception, ceases execution, and proceeds to the end of the program without error.

Differences Between StopIteration and StopAsyncIteration

Standard synchronous iterators raise StopIteration inside __next__. However, raising a standard StopIteration inside an asynchronous __anext__ method is an error.

Under PEP 479, raising StopIteration inside an asynchronous context or coroutine will not cleanly end the loop; instead, Python transforms it into a RuntimeError. Therefore, custom asynchronous iterators must explicitly use StopAsyncIteration to ensure compatibility with asynchronous looping constructs.
