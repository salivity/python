Python Sentinel Values Using object()

In Python, functions often need to differentiate between an argument that was intentionally passed as None and one that was omitted entirely by the caller. Using object() to create a private sentinel value solves this problem by providing a unique object identity that cannot be accidentally supplied by external code, eliminating the ambiguity inherent in standard default parameters.

The Ambiguity of Default Arguments

A standard pattern for handling optional parameters in Python assigns None as the default value:

def update_cache(key, value=None):
    if value is None:
        # Was value omitted, or did the caller explicitly set it to None?
        pass

This approach breaks down when None represents a valid domain value. For example, a cache system might legitimately store None to indicate a cached negative result, or a database updater might use None to set a column to SQL NULL. Because None is a built-in singleton accessible anywhere in Python, checking value is None cannot determine whether the caller passed None deliberately or omitted the argument.

Using other falsey primitives like False, "", or 0 creates the same ambiguity for their respective types.

Resolving Ambiguity with object()

Every call to object() instantiates a distinct object in memory with a unique identity:

_MISSING = object()

Because _MISSING is private to your module or class, outside callers cannot reference it unless you explicitly expose it. When used as a default argument, you can verify presence using the identity operator (is):

_MISSING = object()

def update_cache(key, value=_MISSING):
    if value is _MISSING:
        # Argument was omitted by the caller
        fetch_and_cache(key)
    else:
        # Argument was explicitly provided, even if value is None
        write_to_cache(key, value)

With this implementation:

  • update_cache("user_1") detects that value is omitted because value is _MISSING evaluates to True.
  • update_cache("user_1", None) detects that value was explicitly passed because None is _MISSING evaluates to False.

Why object() Is the Ideal Sentinel

  1. Guaranteed Identity Uniqueness: Python’s is operator checks memory address identity. Two separate calls to object() will never evaluate as identical: object() is object() is always False.
  2. Minimal Overhead: The base object class is the most lightweight type in Python, consuming minimal memory and requiring no custom class definitions.
  3. No Accidental Equivalence: Unlike custom classes that might implement __eq__, plain object instances only evaluate equal to themselves. This prevents unintended matches against user inputs that override equality checks.
