Understanding Python radd and Reverse Operators

Reverse operator dunder methods—such as __radd__, __rsub__, and __rmul__—serve as Python's fallback mechanism for binary operations. When an expression like x + y is evaluated, Python first attempts to call the left-hand operand's method (x.__add__(y)). If the left-hand operand does not implement this method or returns the special NotImplemented singleton, Python delegates the operation to the right-hand operand by calling its reflected counterpart (y.__radd__(x)). This article explains how this mechanism ensures interoperability between built-in types and custom user-defined classes.

The Problem of Asymmetric Knowledge

Built-in types like int, float, and list are precompiled and have no knowledge of custom classes written later. If you create a custom class representing a vector, matrix, or currency, you can easily define __add__ to handle addition with an integer:

class Money:
    def __init__(self, amount):
        self.amount = amount

    def __add__(self, other):
        if isinstance(other, (int, float)):
            return Money(self.amount + other)
        return NotImplemented

With only __add__ defined, Money(10) + 5 succeeds because Money.__add__ knows how to handle an int. However, the reverse expression, 5 + Money(10), will fail. The built-in integer class's __add__ method does not know how to add a Money instance, so it returns NotImplemented. Without a fallback, Python would raise a TypeError.

How Reverse Methods Resolve the Failure

To resolve this issue, Python checks whether the right-hand operand implements the corresponding reverse dunder method. By implementing __radd__, the right-hand operand is given a chance to handle the operation:

class Money:
    def __init__(self, amount):
        self.amount = amount

    def __add__(self, other):
        if isinstance(other, (int, float)):
            return Money(self.amount + other)
        return NotImplemented

    def __radd__(self, other):
        # Delegate directly to __add__ since addition is commutative
        return self.__add__(other)

Now, when Python evaluates 5 + Money(10):

  1. Python executes (5).__add__(Money(10)).
  2. The integer's method returns NotImplemented.
  3. Python identifies that the right-hand operand provides __radd__.
  4. Python executes Money(10).__radd__(5).
  5. The operation completes successfully and returns Money(15).

If the right-hand operand also returns NotImplemented or does not implement the reverse method, Python halts the execution and raises a TypeError: unsupported operand type(s).

Non-Commutative Operations

While addition and multiplication are typically commutative (where a + b == b + a), operations like subtraction (__sub__ / __rsub__) and division (__truediv__ / __rtruediv__) are order-dependent. In reverse methods for non-commutative operations, the operands retain their semantic positions:

class CustomNumber:
    def __init__(self, value):
        self.value = value

    def __rsub__(self, other):
        # 'other' is the left operand, 'self' is the right operand
        # This handles: other - self
        return CustomNumber(other - self.value)

When evaluating 10 - CustomNumber(3), the call becomes CustomNumber(3).__rsub__(10), correctly preserving the order of subtraction as 10 - 3.

Subclass Precedence Rule

Python includes an exception to the left-to-right evaluation order for inheritance hierarchies. If the right-hand operand is an instance of a distinct subclass of the left-hand operand's class, Python invokes the subclass's reverse method before the base class's forward method. This guarantees that specialized subclass implementations can override the behavior of their parent classes, maintaining standard object-oriented polymorphism.
