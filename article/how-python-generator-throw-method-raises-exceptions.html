How Python Generator throw Method Raises Exceptions

This article provides an overview of Python's generator .throw() method, explaining the mechanics of how it injects exceptions into a suspended generator's execution frame. It details the state of a suspended generator, the role of Python's evaluation loop, how the interpreter switches execution context to simulate an error at the point of suspension, and the resulting control flow depending on whether the generator handles or propagates the exception.

Generator Frame Suspension

To understand .throw(), you must first understand how Python suspends generators. When a generator encounters a yield statement, execution halts, but its state is not destroyed. The interpreter preserves the generator's execution frame (PyFrameObject in CPython), which holds:

  • The local variable scope.
  • The evaluation stack.
  • The instruction pointer (the exact bytecode instruction where execution paused).

The generator transitions to the GEN_SUSPENDED state, yielding control back to the caller while retaining its entire execution context in memory.

The Invocation of .throw()

The .throw() method accepts an exception type, an optional value, and an optional traceback:

generator.throw(typ[, val[, tb]])

When called, .throw() does not raise the exception inside the caller's current scope immediately. Instead, it passes the exception information to CPython's internal generator evaluation function (historically gen_send_ex in Objects/genobject.c).

While .send(value) resumes the frame by pushing a normal value onto the generator’s value stack, .throw() sets an exception state directly on the thread state (PyThreadState) targeting that specific frame.

Raising the Exception Inside the Frame

Once the interpreter switches context back to the generator’s frame, the bytecode evaluation loop (_PyEval_EvalFrameDefault) resumes execution at the instruction pointer where the generator was suspended.

Instead of continuing normal execution:

  1. Simulating Failure at the Yield Point: The interpreter treats the suspension point—specifically the YIELD_VALUE (or SEND) bytecode instruction—as having failed.
  2. Injecting the Exception: The virtual machine inspects the exception passed through .throw(). It formats it into a full Python exception object with tracebacks attached and sets it as the active exception in the generator frame.
  3. Triggering Stack Unwinding: The evaluation loop immediately branches into its exception handling routine, unwinding the generator frame’s block stack as if the yield expression itself had raised the error.

Control Flow Outcomes

Once the exception is raised inside the frame, execution proceeds based on the generator's internal structure:

1. The Exception Is Caught

If the yield expression is enclosed within a matching try...except block inside the generator:

def my_gen():
    try:
        yield 1
    except ValueError:
        yield 2

The generator's frame catches the injected exception and proceeds to execute the handler. If execution subsequently reaches another yield statement, the generator pauses again, and the yielded value becomes the return value of the caller's .throw() call.

2. The Exception Is Unhandled

If the generator does not catch the exception:

def my_gen():
    yield 1
    # No try/except block

The exception unwinds the entire frame of the generator. The generator's state is permanently set to GEN_CLOSED, its frame resources are cleaned up, and the exception bubbles out of the generator frame back into the caller's execution frame at the line where .throw() was invoked.
