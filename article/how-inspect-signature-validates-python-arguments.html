How inspect.signature Validates Python Arguments

Python's inspect.signature() introspects callable objects to extract parameter specifications, providing programmatic tools to bind and validate runtime arguments against that definition. This article explains how Python extracts metadata from a callable's code object, constructs Signature and Parameter instances, uses .bind() and .bind_partial() to align arguments, and enforces execution constraints before a function runs.

Extracting the Signature

When you pass a callable to inspect.signature(callable), Python examines the underlying metadata of the target object. For standard functions, it inspects attributes such as __code__, __defaults__, __kwdefaults__, and __annotations__.

The function's code object (__code__) holds fundamental layout data, including:

  • co_varnames: Local variable names, where the first entries are the parameter names.
  • co_argcount: Total number of positional arguments (including positional-only and positional-or-keyword).
  • co_posonlyargcount: Number of positional-only arguments.
  • co_kwonlyargcount: Number of keyword-only arguments.
  • co_flags: Bit flags indicating whether the function accepts *args (CO_VARARGS) or **kwargs (CO_VARKEYWORDS).

If the callable is wrapped (e.g., using functools.wraps), inspect.signature() automatically follows the __wrapped__ chain by default to inspect the original underlying function.

The result is a Signature object containing a mapping of parameter names to Parameter objects in sig.parameters. Each Parameter defines:

  • name: The identifier of the parameter.
  • default: The default value, or Parameter.empty if none exists.
  • annotation: The type hint, or Parameter.empty if unannotated.
  • kind: One of five parameter categories:
    1. POSITIONAL_ONLY
    2. POSITIONAL_OR_KEYWORD
    3. VAR_POSITIONAL (*args)
    4. KEYWORD_ONLY
    5. VAR_KEYWORD (**kwargs)

Binding Arguments

Once a Signature object is generated, argument validation occurs via the Signature.bind(*args, **kwargs) or Signature.bind_partial(*args, **kwargs) methods.

import inspect

def process_data(item_id: int, mode: str = "fast", *tags, notify: bool = False):
    pass

sig = inspect.signature(process_data)
bound_args = sig.bind(42, "slow", "tag1", "tag2", notify=True)

The binding algorithm iterates through the supplied *args and **kwargs and maps them to the ordered list of Parameter definitions according to their kind:

  1. Positional Matching: It consumes positional arguments from *args to fulfill POSITIONAL_ONLY and POSITIONAL_OR_KEYWORD parameters sequentially. If extra positional values remain, they are assigned to the VAR_POSITIONAL parameter (*args). If no variable positional parameter exists and extra arguments are supplied, a TypeError is raised.
  2. Keyword Matching: It matches entries from **kwargs against unfulfilled POSITIONAL_OR_KEYWORD parameters and KEYWORD_ONLY parameters. Unmatched keyword arguments are assigned to the VAR_KEYWORD parameter (**kwargs). If unexpected keyword arguments are passed without a variable keyword sink, a TypeError is raised.
  3. Collision Detection: If an argument is provided positionally and the same parameter name is passed via **kwargs, the binder detects the duplicate assignment and raises a TypeError.
  4. Completeness Check: bind() ensures that all parameters without defaults have been assigned a value. If any required parameter is missing, it raises a TypeError: missing a required argument.

The bind_partial() method follows the identical assignment logic but skips the completeness check, making it useful for currying, partial applications, or validating incremental inputs.

Applying Defaults and Accessing Values

The output of a successful binding operation is a BoundArguments instance. It holds:

  • bound_args.arguments: An OrderedDict mapping parameter names to the passed argument values.
  • bound_args.args: A tuple of positional arguments aligned to the callable.
  • bound_args.kwargs: A dictionary of keyword arguments aligned to the callable.

By default, bound_args.arguments only contains values explicitly passed during the binding call. To populate default parameter values defined in the signature, invoke apply_defaults():

bound_args = sig.bind(101)
bound_args.apply_defaults()

# bound_args.arguments now contains:
# {'item_id': 101, 'mode': 'fast', 'tags': (), 'notify': False}

Runtime Validation Workflow

Because bind() raises standard Python exceptions without actually executing the callable, it can be used in decorators, RPC frameworks, or API routing layers to validate inputs ahead of time.

def validate_call(func, *args, **kwargs):
    sig = inspect.signature(func)
    try:
        bound = sig.bind(*args, **kwargs)
        bound.apply_defaults()
        return bound.arguments
    except TypeError as exc:
        raise ValueError(f"Invalid call signature for {func.__name__}: {exc}") from exc

This pattern leverages Python's built-in parameter-resolution rules to guarantee that incoming arguments conform structurally to the callable's signature before downstream processing occurs.
