Using typing.ClassVar in Python Dataclasses

Python's dataclasses module inspects type annotations on a class to automatically generate special methods like __init__, __repr__, and __eq__. By default, any annotated variable is treated as an instance attribute. This article explains how typing.ClassVar acts as a special marker that instructs the dataclass code generator to exclude a variable from instance-level processing and retain it purely as a shared, class-level attribute.

The Default Dataclass Behavior

When you decorate a class with @dataclass, Python looks at the class's __annotations__ dictionary. Every annotated variable is registered as a dataclass field.

from dataclasses import dataclass

@dataclass
class Product:
    name: str
    price: float
    tax_rate: float = 0.05

In the example above, tax_rate is considered an instance attribute with a default value of 0.05. Because of this, it is included as a parameter in the auto-generated __init__ method:

item = Product(name="Book", price=10.0, tax_rate=0.08)

Even though you may have intended tax_rate to be shared globally across all Product instances, the dataclass treats it as an instance attribute because it has a standard type annotation.

How typing.ClassVar Changes Field Detection

To declare an attribute that belongs to the class itself rather than individual instances, Python provides typing.ClassVar.

When the @dataclass decorator inspects annotations, it checks whether an annotation is wrapped in ClassVar. If it detects ClassVar, the decorator skips that attribute when building the dataclass fields.

from dataclasses import dataclass
from typing import ClassVar

@dataclass
class Product:
    name: str
    price: float
    tax_rate: ClassVar[float] = 0.05

Because tax_rate is wrapped in ClassVar[float]:

  1. Excluded from __init__: It is not added to the parameters of the generated __init__ method. Calling Product("Book", 10.0, 0.08) will raise a TypeError.
  2. Excluded from Comparison and Representation: Methods like __repr__, __eq__, and __hash__ will ignore tax_rate. Printing Product("Book", 10.0) outputs Product(name='Book', price=10.0).
  3. Excluded from Helper Functions: Functions like dataclasses.fields() and dataclasses.asdict() completely ignore ClassVar fields.

Access and Mutation

A ClassVar behaves like any standard class variable in standard Python object-oriented programming:

  • Access: You can access it via the class (Product.tax_rate) or through an instance (item.tax_rate).
  • Class Modification: Changing it via the class (Product.tax_rate = 0.10) updates the value for all instances that have not overridden it.
  • Instance Modification: Assigning a value via an instance (item.tax_rate = 0.10) creates an instance attribute on item that shadows the class-level variable, leaving Product.tax_rate unchanged for other instances.

By using typing.ClassVar, you maintain clear static typing while explicitly preventing dataclass machinery from treating shared class attributes as instance-level fields.
