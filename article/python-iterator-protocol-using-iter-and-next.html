Python Iterator Protocol: Using iter and next

The Python iterator protocol provides a standardized mechanism for traversing sequences and collections sequentially without loading entire datasets into memory at once. At the heart of this protocol are two dunder (double underscore) methods: __iter__ and __next__. When combined, they allow any custom class to define its own iteration behavior, enabling seamless integration with Python's native iteration tools, including for loops, comprehensions, and generator expressions.

Iterables vs. Iterators

To understand the protocol, you must distinguish between an iterable and an iterator:

  • Iterable: An object capable of returning its members one at a time. It implements the __iter__ method, which must return an iterator object.
  • Iterator: The actual stream-producing object. It must implement both __next__, to fetch successive values, and __iter__, to return itself so that it can also be used wherever an iterable is expected.

The Role of __iter__

The __iter__ method initializes the iteration state and returns an iterator. In built-in collections like lists and dictionaries, calling iter(collection) triggers collection.__iter__(), which creates a separate iterator object.

For a dedicated iterator class, __iter__ typically returns self. This self-referential requirement guarantees that an iterator can directly be passed into constructs expecting an iterable:

def __iter__(self):
    return self

The Role of __next__

The __next__ method advances the iteration state and returns the next item in the sequence. Each invocation moves an internal pointer forward.

When there are no more items to return, __next__ must raise the StopIteration exception. Python uses this specific exception as a control signal to end iteration loops safely without crashing the program.

Implementing the Protocol: A Complete Example

Here is how __iter__ and __next__ work together in a custom counter class:

class CountDown:
    def __init__(self, start):
        self.current = start

    def __iter__(self):
        return self

    def __next__(self):
        if self.current <= 0:
            raise StopIteration
        
        value = self.current
        self.current -= 1
        return value

How Python Consumes the Iterator

When you iterate over an instance of CountDown using a standard for loop:

for number in CountDown(3):
    print(number)

Python executes the following steps behind the scenes:

  1. Retrieves the iterator: It calls iter(CountDown(3)), which invokes CountDown.__iter__().
  2. Retrieves elements: It repeatedly calls next(iterator), which invokes CountDown.__next__(), returning 3, 2, and 1.
  3. Terminates: When self.current reaches 0, __next__ raises StopIteration. The for loop catches this exception internally and exits cleanly.
