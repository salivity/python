How to Use Python setattr to Intercept Attributes

In Python, intercepting attribute assignment allows you to dynamically validate, modify, or restrict changes to an object's state at runtime. This article explains how the __setattr__ magic method works, how to implement it correctly to avoid common pitfalls like infinite recursion, and provides practical code examples demonstrating its use in class design.

Understanding __setattr__

The __setattr__ method is invoked automatically whenever an attribute assignment is attempted on an object instance. The method signature takes three arguments:

def __setattr__(self, name: str, value: any) -> None:
    pass

Whenever you write instance.attribute = value, Python translates that operation into instance.__setattr__('attribute', value).

Avoiding the Infinite Recursion Pitfall

The most common mistake when overriding __setattr__ is assigning a value using standard assignment syntax:

# INCORRECT: Causes RecursionError
class BadExample:
    def __setattr__(self, name, value):
        self.name = value  # Triggers __setattr__ again, leading to an infinite loop

Because self.name = value triggers __setattr__ again, the code loops infinitely until a RecursionError is raised.

To prevent this, you must route the assignment through the base class using super() or by directly modifying the instance's __dict__. The standard and recommended approach in modern Python is using super():

# CORRECT
class GoodExample:
    def __setattr__(self, name, value):
        super().__setattr__(name, value)

Implementing __setattr__ for Validation

A common use case for __setattr__ is enforcing data validation or transforming values dynamically before they are stored.

class User:
    def __init__(self, username, age):
        self.username = username
        self.age = age

    def __setattr__(self, name, value):
        if name == "age":
            if not isinstance(value, int) or value < 0:
                raise ValueError("Age must be a positive integer.")
        elif name == "username":
            if not isinstance(value, str) or len(value.strip()) == 0:
                raise ValueError("Username must be a non-empty string.")
            value = value.strip().lower()

        # Delegate the actual storage to the base class
        super().__setattr__(name, value)

In this implementation:

  • Assigning user.age = -5 or user.age = "twenty" immediately raises a ValueError.
  • Assigning user.username = " Alice " automatically cleans and lowercases the string to "alice".
  • Any other attributes pass through unchanged to super().__setattr__.

Creating Read-Only or Frozen Classes

You can also use __setattr__ to restrict attribute modification entirely after initialization, creating immutable or "frozen" objects:

class FrozenPoint:
    def __init__(self, x, y):
        super().__setattr__("x", x)
        super().__setattr__("y", y)
        super().__setattr__("_initialized", True)

    def __setattr__(self, name, value):
        if getattr(self, "_initialized", False):
            raise AttributeError(f"Cannot modify immutable instance attribute '{name}'.")
        super().__setattr__(name, value)

Once the _initialized flag is set to True, any subsequent assignment like point.x = 10 raises an AttributeError.

When to Use __setattr__ vs @property

Use @property when you only need to control a specific, known attribute. Reserve __setattr__ for scenarios where you need to intercept all attribute assignments globally, such as building dynamic proxies, creating custom ORMs, or enforcing universal type-checking across an entire class.
