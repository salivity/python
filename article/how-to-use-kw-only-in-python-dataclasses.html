How to Use KW_ONLY in Python Dataclasses

Python 3.10 introduced dataclasses.KW_ONLY, a sentinel value used in dataclass definitions to designate specific fields as keyword-only. In Python dataclasses, all fields defined after KW_ONLY cannot be passed as positional arguments when instantiating the class; they must be provided using their explicit parameter names. This mechanism improves code readability, prevents accidental argument misplacement, and solves common issues related to default argument ordering during class inheritance.

How KW_ONLY Works

In standard Python, positional arguments must precede keyword arguments with defaults. In dataclasses, this rule often causes issues: a subclass defining a required field without a default cannot easily inherit from a parent class that has fields with defaults. Placing KW_ONLY into the dataclass body marks everything below it as keyword-only in the automatically generated __init__ method.

To use it, assign the type annotation KW_ONLY to a dummy variable (typically an underscore _):

from dataclasses import dataclass, KW_ONLY

@dataclass
class User:
    id: int
    name: str
    _: KW_ONLY
    email: str
    is_active: bool = True

In the generated __init__ signature, this compiles to:

def __init__(self, id: int, name: str, *, email: str, is_active: bool = True):
    ...

Instantiation Rules

With the above definition, id and name can be supplied positionally or by keyword, but email and is_active must be supplied by keyword:

# Valid instantiation:
user1 = User(1, "Alice", email="alice@example.com")
user2 = User(id=2, name="Bob", email="bob@example.com", is_active=False)

# Invalid instantiation (raises TypeError):
user3 = User(1, "Alice", "alice@example.com")

Attempting to pass "alice@example.com" positionally results in a TypeError: User.__init__() takes 3 positional arguments but 4 were given.

Solving Inheritance and Default Field Ordering

One of the primary uses of KW_ONLY is bypassing the requirement that non-default fields cannot follow default fields.

Without KW_ONLY, the following structure fails with a SyntaxError or TypeError because the subclass introduces a non-default field (role) after the parent's default field (created_at):

@dataclass
class BaseItem:
    id: int
    created_at: str = "2024-01-01"

@dataclass
class Employee(BaseItem):
    role: str  # SyntaxError: non-default argument 'role' follows default argument

By marking the fields as keyword-only, Python allows required fields without default values to appear after fields with default values:

@dataclass
class BaseItem:
    id: int
    _: KW_ONLY
    created_at: str = "2024-01-01"

@dataclass
class Employee(BaseItem):
    role: str

# Valid: created_at and role are both keyword-only
emp = Employee(101, role="Developer")

KW_ONLY vs. field(kw_only=True)

Python also provides a field-level parameter: field(kw_only=True). While field(kw_only=True) must be applied individually to each desired field, _ : KW_ONLY serves as a delimiter that marks all subsequently defined fields in the class as keyword-only. Additionally, passing kw_only=True to the @dataclass decorator itself makes every single field in the dataclass keyword-only.
