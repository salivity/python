Python LOAD_CONST Bytecode Optimization Explained

This article explores how Python optimizes repeated access to constant literals at compile-time and runtime through the LOAD_CONST bytecode instruction. When executing code, CPython avoids dynamic object creation and expensive dictionary lookups by pre-allocating literals into an immutable tuple on the code object called co_consts. By combining compile-time constant folding, literal deduplication, and direct index-based memory access, the CPython virtual machine ensures that accessing literal values requires minimal computational overhead.

Compile-Time Storage and co_consts

Python analyzes source code and builds an Abstract Syntax Tree (AST) before generating bytecode. During this compilation phase, any immutable literals—such as integers, floats, strings, booleans, and frozen sets—are instantiated and stored within the co_consts attribute of the corresponding code object (PyCodeObject).

Instead of allocating memory for a number like 42 or a string like "data" every time the line of code runs, Python creates the underlying PyObject once during compilation. The resulting bytecode references this object via its numeric index inside the co_consts tuple.

Constant Folding and Literal Deduplication

Python’s compiler implements an optimization step known as constant folding. When an expression contains only literal values (such as 60 * 60 * 24), the compiler evaluates this operation ahead of time and replaces the expression with the calculated literal (86400).

Additionally, the compiler deduplicates identical constants within the same compilation unit. If a function references the string "active" in several distinct locations, CPython normally stores only a single instance of "active" in co_consts. Both locations in bytecode will point to the same index in the tuple, reducing memory footprint and preserving cache locality.

Mechanics of the LOAD_CONST Instruction

At runtime, the Python virtual machine evaluates instructions via an evaluation loop (historically ceval.c). When the interpreter encounters a constant, it uses the LOAD_CONST opcode accompanied by an integer argument representing the index in co_consts.

import dis

def calculate_total(price):
    return price + 1.25

dis.dis(calculate_total)

The disassembled bytecode shows the direct reference:

2           0 LOAD_FAST                0 (price)
            2 LOAD_CONST               1 (1.25)
            4 BINARY_ADD
            6 RETURN_VALUE

The execution of LOAD_CONST operates as follows:

  1. O(1) Array Indexing: The interpreter reads the oparg (in this case, 1) and performs an array index operation into the code object's constants array (PyTuple_GET_ITEM(co->co_consts, oparg)). This bypasses the hash table lookups required by LOAD_GLOBAL or LOAD_NAME.
  2. Reference Increment: The interpreter increments the reference count of the pre-existing object using Py_INCREF.
  3. Stack Push: The pointer to the constant is pushed directly onto the evaluation value stack.

Performance Advantages

By shifting the work of object creation and expression evaluation to compile time, LOAD_CONST reduces runtime operations to a simple pointer retrieval. Because the co_consts structure is fixed and immutable, repeated executions of loops or frequently called functions encounter zero allocation overhead for their literals, allowing the virtual machine to operate at optimal execution speeds.
