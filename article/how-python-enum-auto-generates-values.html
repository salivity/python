How Python enum.auto Generates Values

This article explores the internal mechanics of Python's enum.auto(), detailing how the standard enum module assigns automatic sequential values to enumerated constants. It breaks down the interaction between the auto instance, the enumeration metaclass, and the underlying _generate_next_value_ method that calculates values, while also demonstrating how to customize this behavior.

The Role of the auto Instance

When you assign auto() to an enum member, you are not directly assigning a final number. Instead, auto() instantiates an auto class object. This object acts as a temporary marker or sentinel inside the class definition, signaling to Python that the value for this specific attribute must be determined programmatically during class creation rather than taken as a literal.

from enum import Enum, auto

class Color(Enum):
    RED = auto()
    GREEN = auto()
    BLUE = auto()

Metaclass Processing

Python enums are constructed using a specialized metaclass: EnumType (named EnumMeta prior to Python 3.11). When defining an Enum subclass, Python evaluates the class body inside a custom mapping called _EnumDict.

During class construction, the metaclass iterates through the namespace attributes. When it encounters an attribute whose assigned value is an instance of auto, it intercepts it. Rather than setting the attribute value to the auto instance itself, the metaclass invokes the class's _generate_next_value_ method to compute the actual value.

The _generate_next_value_ Hook

The core calculation logic resides in a static or class method named _generate_next_value_. Defined on the base Enum class, this method has the following general signature:

_generate_next_value_(name, start, count, last_values)
  • name: The name of the member being defined (e.g., "RED").
  • start: The starting integer for the sequence (defaults to 1).
  • count: The number of members defined so far.
  • last_values: A list containing all previously assigned member values.

By default, standard Enum implementations compute the next integer sequentially. If last_values is empty, it assigns 1 (or the configured start). If last_values contains prior values, it takes the highest numerical value found or adds 1 to the previous count, ensuring every subsequent call yields an incremented integer (1, 2, 3, ...). Once the value is computed, the metaclass replaces the placeholder auto instance with the generated integer and finalizes the member.

Customizing Automatic Values

Because _generate_next_value_ is an internal hook, it can be overridden to change how sequential values are produced. The override must be defined before any enum members are declared.

For example, to make auto() return the lowercase name of each member as a string instead of an integer:

class State(Enum):
    def _generate_next_value_(name, start, count, last_values):
        return name.lower()

    PENDING = auto()   # Value becomes "pending"
    RUNNING = auto()   # Value becomes "running"
    COMPLETED = auto() # Value becomes "completed"

Through this metaclass-driven design, Python cleanly separates the declaration marker (auto()) from the value assignment algorithm (_generate_next_value_), allowing for predictable, collision-free sequential values by default.
