How importlib.metadata Inspects Python Packages

Python's importlib.metadata standard library module provides a unified API for inspecting installed third-party distributions without executing or importing their code. It achieves this by leveraging the import system to locate package metadata directories (.dist-info or .egg-info) across sys.path, parsing standardized plain-text metadata files to retrieve distribution versions, registered entry points, and declared project requirements.

Locating Distribution Metadata

The retrieval process begins with MetadataPathFinder, a built-in meta path finder registered in sys.meta_path. When a query is initiated, the finder searches each directory in sys.path for folders ending in .dist-info (defined by PEP 376) or legacy .egg-info.

A .dist-info directory contains standardized text files generated during the build and install phases (such as pip install). Rather than loading Python bytecode, importlib.metadata.distribution('package-name') locates the corresponding directory and reads its static text records directly from disk or compressed zip archives.

Extracting Distribution Versions

To extract a distribution's version, importlib.metadata.version('package-name') accesses the METADATA file (or PKG-INFO in .egg-info directories) inside the package's .dist-info directory.

This file is formatted as an RFC 822 email header message defined by Python Core Metadata specifications (PEP 566, PEP 643). The module uses an internal email-style message parser to read the key-value headers. It reads the value corresponding to the Version: key and returns it as a string, completely bypassing the package's runtime __version__ attribute.

from importlib.metadata import version

pkg_version = version("requests")

Parsing Entry Points

Entry points enable packages to register plugins or command-line scripts. These mappings are stored inside .dist-info/entry_points.txt using an INI-style format. Sections in the file define entry point groups, while individual lines map named identifiers to module paths and callables:

[console_scripts]
black = black:patched_main

When calling importlib.metadata.entry_points(), the module reads entry_points.txt, groups definitions by section, and constructs EntryPoint objects. Each EntryPoint object retains references to the name, group, and target value (e.g., module:attribute). If the caller executes entry_point.load(), importlib dynamically imports the specified module and resolves the object attribute on demand.

from importlib.metadata import entry_points

scripts = entry_points(group="console_scripts")
black_cmd = scripts["black"]

Resolving Dependencies

Dependencies are also extracted from the METADATA file. When calling importlib.metadata.requires('package-name'), the module scans the parsed metadata headers for all occurrences of the Requires-Dist: field.

Each Requires-Dist: entry contains a dependency specification compliant with PEP 508, including package names, version constraints, and optional environment markers (such as Python version or platform checks):

Requires-Dist: urllib3<3,>=1.21.1
Requires-Dist: certifi>=2017.4.17
Requires-Dist: PySocks!=1.5.7,>=1.5.6; extra == "socks"

The requires() function reads these keys into a list of strings representing the declared distribution dependencies, enabling tools to analyze requirement graphs and environment constraints statically.
